= 在 SANtricity System Manager 中查看不可读扇区日志
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
您可以保存不可读扇区日志并将文件发送给技术支持进行分析。

.关于此任务
不可读扇区日志包含由报告不可恢复媒体错误的驱动器引起的不可读扇区的详细记录。在正常 I/O 期间和修改操作（例如重建）期间检测到不可读扇区。当在存储阵列上检测到不可读扇区时，将显示存储阵列的"需要注意"警报。Recovery Guru 会区分哪些不可读扇区状况需要注意。不可读扇区中包含的任何数据都无法恢复，应被视为丢失。

无法读取的扇区日志可存储多达 1,000 个无法读取的扇区。当无法读取的扇区日志达到 1,000 个条目时，适用以下条件：

* 如果在重建期间检测到新的不可读扇区，则重建将失败，并且不会记录任何条目。
* 对于在 I/O 期间检测到的新的不可读扇区，I/O 会出现故障，并且不会记录任何条目。
+
[NOTE]
====
这些操作包括在溢出之前本应成功的 RAID 5 写入和 RAID 6 写入。

====


[CAUTION]
====
*可能丢失数据* -- 从不可读扇区恢复是一个复杂的过程，可能涉及几种不同的方法。仅在技术支持人员指示时执行此操作。

====
.步骤
. 选择菜单：Support[Support Center > Diagnostics] 选项卡。
. 选择 *View/Clear Unreadable Sectors*。
. 要保存不可读扇区日志：
+
.. 在表的第一列中，您可以选择要保存不可读扇区日志的单个卷（单击每个卷旁边的复选框）或选择所有卷（选择表标题中的复选框）。
+
要查找特定卷，您可以对任何列进行排序或在 *Filter* 框中键入字符。

.. 单击 *Save*。


+
此文件将以此名称保存在浏览器的 Downloads 文件夹中 `unreadable-sectors.txt`。

. 如果技术支持指示您清除不可读扇区日志，请执行以下步骤：
+
.. 在表的第一列中，您可以选择要清除不可读扇区日志的单个卷（单击每个卷旁边的复选框）或选择所有卷（选择表标题中的复选框）。
.. 单击 *Clear*，并确认要执行此操作。
