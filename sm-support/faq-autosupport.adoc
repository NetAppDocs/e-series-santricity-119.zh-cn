[[what-data-am-i-collecting]]
== 我正在收集哪些数据？

AutoSupport 功能和手动支持数据收集功能提供了在客户支持包中收集数据的方法，以便技术支持人员进行远程故障排除和问题分析。

客户支持捆绑包将存储阵列的所有类型信息收集到单个压缩文件中。收集的信息包括物理配置、逻辑配置、版本信息、事件、日志文件和性能数据。这些信息仅由技术支持人员用于解决存储阵列的问题。

== 无法读取的扇区数据向我显示了什么？

您可以显示有关在存储阵列中的驱动器上检测到的不可读扇区的详细数据。

不可读扇区日志首先显示最新的不可读扇区。日志中包含以下有关包含不可读扇区的卷的信息。字段是可排序的。

受影响的卷
 a| 
显示卷的标签。如果缺失的卷包含不可读扇区，则会显示缺失卷的 World Wide Identifier。



 a| 
logical unit number（逻辑单元号）(LUN)
 a| 
显示卷的 LUN。如果卷没有 LUN，对话框将显示 NA。



 a| 
分配给
 a| 
显示有权访问卷的主机或主机群集。如果主机、主机群集甚至 Default Cluster 都无法访问该卷，则对话框将显示 NA。

|===
要查看有关不可读扇区的其他信息，请单击卷旁边的加号 (+)。

[cols="25h,~"]
|===
| 字段 | 说明 


 a| 
日期/时间
 a| 
显示检测到不可读扇区的日期和时间。



 a| 
卷逻辑块地址
 a| 
显示卷的逻辑块地址 (LBA)。



 a| 
驱动器位置
 a| 
显示驱动器架、抽屉（如果您的驱动器架有抽屉）和托架位置。

显示驱动器的 LBA。



 a|

 a|

* *物理* -- 物理介质错误。

* *不一致* -- 冗余数据不一致。
* *数据保证* -- 数据保证错误。

[[what-is-a-health-image]]
== 什么是健康映像？

健康映像是控制器处理器内存的原始数据转储，技术支持可以使用它来诊断控制器的问题。

固件在检测到某些错误时会自动生成运行状况映像。在某些疑难解答情况下，技术支持可能会要求您检索运行状况映像文件并将其发送给他们。



[[what-do-the-autosupport-features-do]]
== 这些 AutoSupport 功能有什么作用？

该 AutoSupport 功能由三个单独的功能组成，您可以分别启用这些功能。

* *基本 AutoSupport* -- 允许您的存储阵列自动收集数据并将其发送给技术支持。
* *AutoSupport OnDemand* -- 允许技术支持在需要解决问题时请求重新传输以前的 AutoSupport 派单。所有传输都是从存储阵列启动的，而不是从 AutoSupport 服务器启动的。存储阵列定期与 AutoSupport 服务器进行检查，以确定是否存在任何挂起的重传请求，并做出相应的响应。
* *远程诊断* -- 允许技术支持在需要解决问题时请求新的最新 AutoSupport 派遣。所有传输都是从存储阵列启动的，而不是从 AutoSupport 服务器启动的。存储阵列定期与 AutoSupport 服务器签入，以确定是否存在任何挂起的新请求，并做出相应的响应。




[[what-type-of-data-is-collected-through-the-autosupport-feature]]
== 通过 AutoSupport 功能收集哪些类型的数据？

AutoSupport 功能包含三种标准调度类型：事件调度、计划调度以及按需和远程诊断调度。

此 AutoSupport 数据不包含任何用户数据。

* *事件调度*
+
当系统上发生需要主动通知技术支持的事件时，AutoSupport 功能会自动发送事件触发的派单。

+
** 在托管存储阵列上发生支持事件时发送。
** 包括事件发生时存储阵列状况的综合快照。


* *计划派单*
+
AutoSupport 功能会按常规时间表自动发送多个派单。

+
** *每日调度* -- 在用户可配置的时间间隔内每天发送一次。包括当前系统事件日志和性能数据。
** *每周派单* -- 在用户可配置的时间间隔和日期内每周发送一次。包括配置和系统状态信息。


* *AutoSupport OnDemand 和远程诊断派遣*
+
** *AutoSupport OnDemand* -- 允许技术支持在需要解决问题时请求重新传输以前的 AutoSupport 派单。所有传输都是从存储阵列启动的，而不是从 AutoSupport 服务器启动的。存储阵列定期与 AutoSupport 服务器进行检查，以确定是否存在任何挂起的重传请求，并做出相应的响应。
** *远程诊断* -- 允许技术支持在需要解决问题时请求新的最新 AutoSupport 派遣。所有传输都是从存储阵列启动的，而不是从 AutoSupport 服务器启动的。存储阵列定期与 AutoSupport 服务器签入，以确定是否存在任何挂起的新请求，并做出相应的响应。






[[how-do-i-configure-the-delivery-method-for-the-autosupport-feature]]
== 如何为 AutoSupport 功能配置交付方式？

AutoSupport 功能支持 HTTPS 和 SMTP 协议，用于将 AutoSupport 调度发送到技术支持。

.开始之前
* 必须启用 AutoSupport 功能。您可以在 AutoSupport 页面上查看是否已启用此功能。
* 必须在网络中安装和配置 DNS 服务器。必须在 System Manager 中配置 DNS 服务器地址（此任务可从硬件页面获得）。


.关于此任务
查看不同的协议：

* *HTTPS* -- 允许您使用 HTTPS 直接连接到目标技术支持服务器。如果要启用 AutoSupport OnDemand 或远程诊断，必须将 AutoSupport 传递方法设置为 HTTPS。
* *电子邮件* -- 允许您使用电子邮件服务器作为发送 AutoSupport 派单的传递方法。


[NOTE]
====
*HTTPS 和电子邮件方法之间的差异*。使用 SMTP 的电子邮件传递方法与 HTTPS 传递方法有一些重要区别。首先，电子邮件方法的调度大小限制为 5MB，这意味着某些 ASUP 数据集将不会被调度。其次，AutoSupport OnDemand 功能仅在 HTTPS 传递方法上可用。

====
.步骤
. 选择菜单：Support[Support Center > AutoSupport] 选项卡。
. 选择 *配置 AutoSupport 交付方式*。
+
此时将显示一个对话框，其中列出了派单交付方法。

. 选择所需的交付方法，然后为该交付方法选择参数。执行以下操作之一：
+
** 如果选择了 HTTPS，请选择以下交付参数之一：
+
*** *直接* -- 此交付参数是默认选择。选择此选项后，您可以使用 HTTPS 协议直接连接到目标技术支持系统。
*** *通过代理服务器* -- 选择此选项可指定与目标技术支持系统建立连接所需的 HTTP 代理服务器详细信息。必须指定主机地址和端口号。但是，如果需要，只需输入主机身份验证详细信息（用户名和密码）。
*** *通过代理自动配置脚本 (PAC)* -- 指定代理自动配置 (PAC) 脚本文件的位置。PAC 文件允许系统自动选择适当的代理服务器，以建立与目标技术支持系统的连接。


** 如果选择"电子邮件"，请输入以下信息：
+
*** 邮件服务器地址作为完全限定域名、IPv4 地址或 IPv6 地址。
*** AutoSupport 调度电子邮件"发件人"字段中显示的电子邮件地址。
*** *可选；如果要执行配置测试。*AutoSupport 系统收到测试派单时发送确认的电子邮件地址。
*** 如果要加密邮件，请选择 *SMTPS* 或 *STARTTLS* 作为加密类型，然后选择加密邮件的端口号。否则，请选择 *None*。
*** 如果需要，请输入用户名和密码，以便与传出发件人和邮件服务器进行身份验证。




. 单击 *测试配置* 以使用指定的交付参数测试与技术支持服务器的连接。如果您启用了 AutoSupport 按需功能，系统还将测试 AutoSupport OnDemand 派单交付的连接。
+
如果配置测试失败，请检查您的配置设置并再次运行测试。如果测试继续失败，请联系技术支持。

. 单击 *Save*。




[[what-is-configuration-data]]
== 什么是配置数据？

选择收集配置数据时，系统会保存 RAID 配置数据库的当前状态。

RAID 配置数据库包括控制器上卷组和磁盘池的所有数据。"收集配置数据"功能保存的信息与 CLI 命令 `save storageArray dbmDatabase`相同。



[[what-do-i-need-to-know-before-upgrading-the-santricity-os-software]]
== 在升级 SANtricity 操作系统软件之前，我需要知道什么？

在升级控制器的软件和固件之前，请注意这些项目。

* 您已阅读文档和  `readme.txt` 文件，并确定要进行升级。
* 您知道是否要升级 IOM 固件。
+
通常情况下，您应该同时升级所有组件。但是，如果不想在 SANtricity 操作系统控制器软件升级过程中升级 IOM 固件，或者技术支持指示您降级 IOM 固件（只能使用命令行界面降级固件），则可能决定不升级 IOM 固件。

* 您知道是否要升级控制器 NVSRAM 文件。
+
通常，应同时升级所有组件。但是，如果文件已修补或为自定义版本并且不希望覆盖它，则可能决定不升级控制器 NVSRAM 文件。

* 您知道要立即激活还是稍后激活。
+
稍后激活的原因可能包括：

+
** *时间* -- 激活软件和固件可能需要很长时间，因此您可能需要等待 I/O 负载较轻。控制器在激活期间发生故障转移，因此在升级完成之前，性能可能会低于正常水平。
** *包类型* -- 在升级其他存储阵列上的文件之前，您可能需要在一个存储阵列上测试新软件和固件。




这些组件是 SANtricity 操作系统控制器软件升级的一部分：

* *管理软件* -- System Manager 是管理存储阵列的软件。
* *控制器固件* -- 控制器固件管理主机和卷之间的 I/O。
* *控制器 NVSRAM* -- 控制器 NVSRAM 是一个控制器文件，用于指定控制器的默认设置。
* *IOM 固件* -- I/O 模块 (IOM) 固件管理控制器和驱动器架之间的连接。它还监控组件的状态。
* *Supervisor 软件* -- Supervisor 软件是运行该软件的控制器上的虚拟机。


作为升级过程的一部分，可能还需要升级主机的多路径/故障转移驱动程序和/或 HBA 驱动程序，以便主机可以与控制器正确交互。

[NOTE]
====
要确定是否属于这种情况，请参见 https://mysupport.netapp.com/matrix["NetApp 互操作性表工具"^]。

====
如果您的存储阵列仅包含一个控制器，或者您没有安装多路径驱动程序，请停止对存储阵列的 I/O 活动，以防止出现应用程序错误。如果您的存储阵列有两个控制器，并且您安装了多路径驱动程序，则无需停止 I/O 活动。


CAUTION: 请勿在升级过程中更改存储阵列。



[[what-do-i-need-to-know-before-suspending-iom-auto-synchronization]]
== 在暂停 IOM 自动同步之前，我需要知道什么？

暂停 IOM 自动同步可防止 IOM 固件在下次发生 SANtricity 操作系统控制器软件升级时进行升级。

通常，控制器软件和 IOM 固件作为捆绑包进行升级。如果要在存储模块上保留特殊版本的 IOM 固件，则可以暂停 IOM 自动同步。否则，下次执行控制器软件升级时，将恢复到与控制器软件捆绑的 IOM 固件。



[[why-is-my-firmware-upgrade-progressing-so-slowly]]
== 为什么我的固件升级进展如此缓慢？

固件升级进度取决于系统的整体负载。

在驱动器固件的在线升级期间，如果在快速重建过程中发生卷传输，则系统会对传输的卷启动完全重建。此操作可能需要相当长的时间。实际的完整重建时间取决于几个因素，包括重建操作期间发生的 I/O 活动量、卷组中的驱动器数量、重建优先级设置和驱动器性能。



[[what-do-i-need-to-know-before-upgrading-drive-firmware]]
== 在升级驱动器固件之前，我需要知道什么？

在升级驱动器固件之前，请注意这些项目。

* 作为预防措施，请使用磁盘到磁盘备份、卷复制（到不受计划的固件升级影响的卷组）或远程镜像来备份数据。
* 您可能只想升级几个驱动器来测试新固件的行为，以确保其正常工作。如果新固件运行正常，请升级其余驱动器。
* 如果您有任何故障驱动器，请在开始固件升级之前修复它们。
* 如果驱动器可以执行脱机升级，则停止与驱动器关联的所有卷的 I/O 活动。停止 I/O 活动时，不会发生与这些卷关联的配置操作。
* 升级驱动器固件时请勿移除任何驱动器。
* 升级驱动器固件时，请勿对存储阵列进行任何配置更改。




[[how-do-i-choose-which-type-of-upgrade-to-perform]]
== 如何选择要执行的升级类型？

根据池或卷组的状态，选择要在驱动器上执行的升级类型。

* *联机*
+
如果池或卷组支持冗余且为 Optimal，则可以使用 Online 方法升级驱动器固件。Online 方法在存储阵列使用这些驱动器处理相关卷的 I/O 时下载固件。您不必使用这些驱动器停止对关联卷的 I/O。这些驱动器每次升级一个到与驱动器关联的卷。如果驱动器未分配给池或卷组，则可以通过 Online 或 Offline 方法更新其固件。使用 Online 方法升级驱动器固件时，系统性能可能会受到影响。

* *离线*
+
如果池或卷组不支持冗余（RAID 0）或已降级，则必须使用脱机方法升级驱动器固件。脱机方法将_仅在所有 I/O 活动停止时_升级使用这些驱动器的相关卷的固件。您必须停止使用这些驱动器对任何关联卷的所有 I/O。如果驱动器未分配给池或卷组，则可以通过联机或脱机方法更新其固件。
