= 使用 SANtricity System Manager 中的事件日志查看事件
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
您可以查看事件日志，其中提供了存储阵列上发生的事件的历史记录。

.步骤
. 选择菜单：Support[Event Log]。
+
此时将显示事件日志页面。

+
.页面详细信息
[%collapsible]
====
[cols="25h,~"]
|===
| 项目 | 说明 


 a| 
查看所有字段
 a| 
在所有事件和仅关键事件和警告事件之间切换。



 a| 
筛选字段
 a| 
筛选事件。用于仅显示与特定组件、特定事件等相关的事件。



 a| 
选择列图标。
 a| 
允许您选择要查看的其他列。其他列可为您提供有关事件的其他信息。



 a| 
复选框
 a| 
允许您选择要保存的事件。表格标题中的复选框会选择所有事件。



 a| 
日期/时间列
 a| 
事件的日期和时间戳，根据控制器时钟。


NOTE: 事件日志最初根据序列号对事件进行排序。通常，此序列对应于日期和时间。但是，存储阵列中的两个控制器时钟可能不同步。在此情况下，相对于事件以及显示的日期和时间，一些感知到的不一致可能会出现在事件日志中。



 a| 
优先级列
 a| 
存在以下优先级值：

** *严重* -- 存储阵列存在问题。但是，如果您立即采取行动，您可能会防止失去对数据的访问权限。关键事件用于警报通知。所有关键事件都将发送到任何网络管理客户端（通过 SNMP 陷阱）或您配置的电子邮件收件人。
** *警告* -- 发生错误，降低了存储阵列的性能和从另一个错误恢复的能力。
** *信息* -- 与存储阵列相关的非关键信息。




 a| 
组件类型列
 a| 
受事件影响的组件。组件可以是硬件，如驱动器或控制器，也可以是软件，如控制器固件。



 a| 
组件位置列
 a| 
组件在存储阵列中的物理位置。



 a| 
说明列
 a| 
对事件的描述。

*示例* -- `Drive write failure - retries exhausted`



 a| 
Sequence Number 列
 a| 
唯一标识存储阵列的特定日志条目的 64 位数字。此数字随着每个新事件日志条目增加一。要显示此信息，请单击*选择列*图标。



 a| 
事件类型列
 a| 
标识每种记录事件类型的 4 位数字。要显示此信息，请单击 *Select columns* 图标。



 a| 
事件特定代码列
 a| 
此信息由技术支持使用。要显示此信息，请单击 *Select columns* 图标。



 a| 
事件类别列
 a| 
** **故障** – 存储阵列中的组件出现故障；例如，驱动器故障或电池故障。
** **状态更改** – 存储阵列中已更改状态的元素；例如，卷转换为最佳状态，或控制器转换为离线状态。
** **内部** – 不需要用户操作的内部控制器操作；例如，控制器已完成一天的开始。
** **命令** – 已向存储阵列发出的命令；例如，已分配热备盘。
** **错误** – 在存储阵列上检测到错误情况；例如，控制器无法同步和清除缓存，或者在存储阵列上检测到冗余错误。
** **一般** – 不适合任何其他类别的任何事件。要显示此信息，请单击 **选择列** 图标。




 a| 
Logged By 列
 a| 
记录事件的控制器名称。要显示此信息，请单击 **选择列** 图标。

|===
====
. 要从存储阵列中检索新事件，请单击 **刷新**。
+
记录事件并在 Event Log 页面中显示可能需要几分钟的时间。

. 将事件日志保存到文件：
+
.. 选中要保存的每个事件旁边的复选框。
.. 单击 *Save*。
+
此文件将以此名称保存在浏览器的 Downloads 文件夹中 `major-event-log-timestamp.log`。



. 从事件日志中清除事件：
+
事件日志存储大约 8,000 个事件，然后将事件替换为新事件。如果要保留事件，可以将其保存并从事件日志中清除。

+
.. 首先，保存事件日志。
.. 单击 *Clear All*，并确认要执行此操作。
