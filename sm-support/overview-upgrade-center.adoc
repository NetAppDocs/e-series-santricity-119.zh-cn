[[controller-upgrade-overview]]
== 控制器升级概述

您可以升级存储阵列的软件和固件，以获取所有最新功能和错误修复。



[[components-included-in-the-os-controller-upgrade]]
=== OS 控制器升级中包含的组件

几个存储阵列组件包含您可能需要偶尔升级的软件或硬件。

* *管理软件* -- System Manager 是管理存储阵列的软件。
* *控制器固件* -- 控制器固件管理主机和卷之间的 I/O。
* *控制器 NVSRAM* -- 控制器 NVSRAM 是一个控制器文件，用于指定控制器的默认设置。
* *IOM 固件* -- I/O 模块 (IOM) 固件管理控制器和驱动器架之间的连接。它还监控组件的状态。
* *Supervisor 软件* -- Supervisor 软件是运行该软件的控制器上的虚拟机。


image::../media/sam1130-dwg-upgrade-firmware-locations.gif[升级固件位置]

^1^ 控制器盘架；^2^ 驱动器盘架；^3^ 软件、控制器固件、控制器 NVSRAM、主管软件；^4^ 驱动器固件；^5^ IOM 固件；^6^ 驱动器固件

您可以在"软件和固件清单"对话框中查看当前的软件和固件版本。转到菜单：Support[Upgrade Center]，然后单击 *Software and Firmware Inventory* 的链接。

作为升级过程的一部分，主机的多路径/故障转移驱动程序和/或 HBA 驱动程序也可能需要升级，以便主机可以与控制器正确交互。要确定是否属于这种情况，请参见 https://imt.netapp.com/matrix/#welcome["NetApp Interoperability Matrix Tool"^]。



[[when-to-stop-io]]
=== 何时停止 I/O

如果您的存储阵列包含两个控制器，并且您安装了多路径驱动程序，则在升级过程中，存储阵列可以继续处理 I/O。在升级期间，控制器 A 将其所有卷故障转移到控制器 B，升级，取回其卷和控制器 B 的所有卷，然后升级控制器 B。



[[pre-upgrade-health-check]]
=== 升级前运行状况检查

升级前运行状况检查在升级过程中运行。升级前运行状况检查会评估所有存储阵列组件，以确保升级可以继续。以下情况可能会阻止升级：

* 分配的驱动器出现故障
* 正在使用的热备件
* 不完整的卷组
* 正在运行独占操作
* 缺失卷
* 处于非最佳状态的控制器
* 事件日志事件数过多
* 配置数据库验证失败
* 带有旧版本 DACstore 的驱动器


您还可以单独运行升级前运行状况检查，而无需进行升级。



[[drive-upgrade-overview]]
== 驱动器升级概述

驱动器固件控制驱动器的低级操作特性。驱动器制造商会定期发布驱动器固件更新，以添加新功能、提高性能并修复缺陷。



[[online-and-offline-drive-firmware-upgrades]]
=== 在线和离线驱动器固件升级

有两种类型的驱动器固件升级方法：在线和离线。



==== 联机

在线升级期间，驱动器按顺序逐个升级。升级过程中，存储阵列继续处理 I/O。无需停止 I/O。如果驱动器可以执行在线升级，则会自动使用在线方法。

可以执行在线升级的驱动器包括：

* 优化池中的驱动器
* 最佳冗余卷组（RAID 1、RAID 5 和 RAID 6）中的驱动器
* 未分配的驱动器
* 备用热备盘驱动器


执行在线驱动器固件升级可能需要几个小时，使存储阵列面临潜在的卷故障。在以下情况下可能会发生卷故障：

* 在 RAID 1 或 RAID 5 卷组中，在升级卷组中的其他驱动器时，一个驱动器出现故障。
* 在 RAID 6 池或卷组中，在升级池或卷组中的其他驱动器时，两个驱动器出现故障。




==== 离线（并行）

在脱机升级期间，会同时升级相同驱动器类型的所有驱动器。此方法需要停止与所选驱动器关联的卷的 I/O 活动。由于可以同时（并行）升级多个驱动器，因此整体停机时间大大缩短。如果驱动器只能进行脱机升级，则会自动使用脱机方法。

以下驱动器必须使用脱机方法：

* 非冗余卷组中的驱动器 (RAID 0)
* 非最佳池或卷组中的驱动器
* SSD 缓存中的驱动器




[[compatibility]]
=== 兼容性

每个驱动器固件文件都包含有关固件运行所在的驱动器类型的信息。您只能将指定的固件文件下载到兼容的驱动器。System Manager 在升级过程中自动检查兼容性。
