= SANtricity System Manager 中同步镜像的工作原理
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
同步镜像实时复制数据卷，以确保连续可用性。

[NOTE]
====
EF600/EF600C 或 EF300/EF300C 存储阵列上不提供同步镜像。

====
同步镜像通过在两个存储阵列之一发生灾难时提供重要数据的副本，实现零丢失数据的恢复点目标 (RPO)。副本在任何时刻都与生产数据相同，因为每次对主卷执行写入操作时，都会对辅助卷执行写入操作。在使用在主卷上所做的更改成功更新辅助卷之前，主机不会收到写入成功确认。

这种类型的镜像非常适合业务连续性目的，例如灾难恢复。



[[synchronous-mirroring-relationship]]
== 同步镜像关系

同步镜像关系由不同存储阵列上的主卷和辅助卷组成。包含主卷的存储阵列通常位于主站点，并为活动主机提供服务。包含辅助卷的存储阵列通常位于辅助站点，并保存数据的副本。如果主卷的存储阵列不可用，则使用辅助卷，例如，由于主站点完全停电、火灾或硬件故障。



[[synchronous-mirroring-session]]
== 同步镜像会话

同步镜像配置过程涉及将卷配置成对。创建镜像对（由一个存储阵列上的主卷和另一个存储阵列上的辅助卷组成）后，可以开始同步镜像。同步镜像的步骤如下所示。

image::../media/sam-1130-dwg-sync-mirroring-session.gif[同步镜像会话]

. 主机发出写入请求。
. 写入被提交到主卷，传播到远程系统，然后提交到辅助卷。
. 主卷的存储阵列在两个写入操作都成功完成后，向主机系统发送 I/O 完成消息。


保留容量用于记录有关来自主机的传入写入请求的信息。

当主卷的当前控制器所有者收到来自主机的写入请求时，控制器首先将有关写入的信息记录到主卷的保留容量中。然后，它将数据写入主卷。接下来，控制器启动远程写入操作，将受影响的数据块复制到远程存储阵列的辅助卷。

由于主机应用程序必须等待在本地存储阵列上以及通过网络在远程存储阵列上进行写入，因此需要在本地存储阵列和远程存储阵列之间建立非常快速的连接，以保持镜像关系，而不会过度降低本地 I/O 性能。



[[disaster-recovery]]
== 灾难恢复

同步镜像会维护物理上远离数据所在站点的数据副本。如果主站点发生灾难，例如停电或洪水，则可以从辅助站点快速访问数据。

正在执行同步镜像操作时，辅助卷不可用于主机应用程序，因此，在本地存储阵列发生灾难时，可以故障转移到远程存储阵列。要进行故障切换，请将辅助卷提升为主角色。然后，恢复主机能够访问新提升的卷，并且业务运营可以继续。



[[synchronization-settings]]
== 同步设置

创建镜像对时，还可以定义镜像对在通信中断后用于完成重新同步操作的同步优先级和重新同步策略。

如果两个存储阵列之间的通信链路停止工作，主机将继续从本地存储阵列接收确认，以防止访问丢失。当通信链路再次工作时，可以将任何未复制的数据自动或手动重新同步到远程存储阵列。

数据是否自动重新同步取决于镜像对的重新同步策略。自动重新同步策略允许镜像对在链接再次工作时自动重新同步。手动重新同步策略要求您在出现通信问题后手动恢复同步。手动重新同步是推荐的策略。

只能在包含主卷的存储阵列上编辑镜像对的同步设置。



[[unsynchronized-data]]
== 未同步的数据

当主卷的存储阵列无法将数据写入辅助卷时，主卷和辅助卷将不同步。这可能是由于以下问题造成的：

* 本地和远程存储阵列之间的网络问题
* 出现故障的辅助卷
* 正在镜像对上手动挂起同步




[[orphaned-mirrored-pair]]
== 孤立的镜像对

当一侧（主侧或辅助侧）的成员卷已被移除但另一侧未被移除时，存在孤立的镜像对卷。

当恢复阵列间通信且镜像配置的两侧协调镜像参数时，会检测到孤立的镜像对卷。

您可以删除镜像对以更正孤立的镜像对状态。



[[configuration-and-management]]
== 配置和管理

要启用和配置两个阵列之间的镜像，必须使用 Unified Manager 界面。启用镜像后，您可以在 System Manager 中管理镜像对和同步设置。
