[[how-does-asynchronous-mirroring-differ-from-synchronous-mirroring]]
== 异步镜像与同步镜像有何不同？

Asynchronous Mirroring 功能与 Synchronous Mirroring 功能在一个基本方面有所不同：它捕获特定时间点的源卷状态，并仅复制自上次图像捕获以来发生变化的数据。

使用同步镜像，主卷的状态不会在某个时间点捕获，而是将主卷上所做的所有更改反映到辅助卷上。辅助卷每时每刻都与主卷相同，因为使用这种类型的镜像，每次对主卷执行写入操作时，都会对辅助卷执行写入操作。在使用主卷上所做的更改成功更新辅助卷之前，主机不会收到写入成功确认。

使用异步镜像，远程存储阵列未与本地存储阵列完全同步，因此，如果应用程序由于本地存储阵列丢失而需要转换到远程存储阵列，则可能会丢失一些事务。

镜像功能之间的比较：

[cols="1a,1a"]
|===
| 异步镜像 | 同步镜像 


 a| 
*复制方法*



 a| 
* *时间点*
+
镜像按需完成或根据用户定义的时间表自动完成。时间表可以以分钟为单位进行定义。两次同步之间的最短时间为 10 分钟。


 a| 
* *连续*
+
镜像会自动连续执行，从每次主机写入中复制数据。





 a| 
*预留容量*



 a| 
* *多个*
+
每个镜像对都需要一个预留容量卷。


 a| 
* *单个*
+
所有镜像卷都需要单个保留容量卷。





 a| 
*沟通*



 a| 
* *iSCSI 和光纤通道*
+
支持存储阵列之间的 iSCSI 和 Fibre Channel 接口。


 a| 
* *Fibre Channel*
+
仅支持存储阵列之间的 Fibre Channel 接口。





 a| 
*距离*



 a| 
* *无限制*
+
支持本地存储阵列和远程存储阵列之间几乎无限的距离，距离通常仅受网络功能和通道扩展技术的限制。


 a| 
* *受限*
+
通常必须在距离本地存储阵列约 10 km（6.2 miles）的范围内，以满足延迟和应用程序性能要求。



|===


[[why-cant-i-access-my-chosen-mirroring-feature]]
== 为什么我无法访问我选择的镜像功能？

镜像在 SANtricity Unified Manager 界面中配置。

[NOTE]
====
EF600/EF600C 或 EF300/EF300C 存储阵列上不提供同步镜像。

====
要启用和配置两个阵列之间的镜像，请验证以下内容：

* Web Services Proxy 服务必须正在运行。(Unified Manager 与 Web Services Proxy 一起安装在主机系统上。)
* Unified Manager 必须通过 HTTPS 连接在本地主机上运行。
* 必须在 Unified Manager 中发现要用于镜像的两个存储阵列。
* Unified Manager 必须具有存储阵列的有效 SSL 证书。您可以接受自签名证书或从 Unified Manager 安装 CA 签名证书。


有关配置说明，请参见以下内容：

* link:../um-manage/create-asynchronous-mirrored-pair-um.html["创建异步镜像对（在 Unified Manager 中）"]
* link:../um-manage/create-synchronous-mirrored-pair-um.html["创建同步镜像对（在 Unified Manager 中）"]




[[what-do-i-need-to-know-before-creating-a-mirror-consistency-group]]
== 在创建镜像一致性组之前，我需要知道什么？

在创建镜像一致性组之前，请遵循这些指南。

[NOTE]
====
EF600/EF600C 或 EF300/EF300C 存储系统上不提供同步镜像。

====
您可以在 Unified Manager 的"创建镜像对"向导中创建一致性组。

满足 Unified Manager 的以下要求：

* Web Services Proxy 服务必须正在运行。
* Unified Manager 必须通过 HTTPS 连接在本地主机上运行。
* Unified Manager 必须显示存储阵列的有效 SSL 证书。您可以使用 Unified Manager 接受自签名证书或安装您自己的安全证书，并导航到菜单：Certificate[Certificate Management]。


此外，请务必满足存储阵列的以下要求：

* 必须在 Unified Manager 中发现两个存储阵列。
* 每个存储阵列必须有两个控制器。
* 主阵列和辅助阵列中的每个控制器都必须配置以太网管理端口，并且必须连接到您的网络。
* 存储阵列的最低固件版本为 7.84。（它们可以各自运行不同的 OS 版本。）
* 您必须知道本地和远程存储阵列的密码。
* 您的本地和远程存储阵列通过光纤通道结构或 iSCSI 接口连接。




[[asynchronous-mirroring-what-do-i-need-to-know-before-creating-a-mirrored-pair]]
== 异步镜像 - 在创建镜像对之前，我需要知道什么？

您可以在 SANtricity Unified Manager 界面中配置镜像对，然后在 SANtricity System Manager 中管理这些对。

在创建镜像对之前，请遵循以下指南。

* 您必须有两个存储阵列。
* 每个存储阵列必须有两个控制器。
* 主阵列和辅助阵列中的每个控制器都必须配置以太网管理端口，并且必须连接到您的网络。
* 您的本地和远程存储阵列通过光纤通道结构或 iSCSI 接口连接。
* 存储阵列的最低固件版本为 7.84。（它们可以各自运行不同的 OS 版本。）
* 您必须知道本地和远程存储阵列的密码。
* 必须在远程存储阵列上具有足够的可用容量，才能创建等于或大于要镜像的主卷的辅助卷。
* 您已安装 Web Services Proxy 和 Unified Manager。镜像对在 Unified Manager 界面中配置。
* 在 Unified Manager 中发现两个存储阵列。
* 您的存储阵列必须至少包含一个镜像一致性组。您可以在 Unified Manager 的"创建镜像对"向导中创建一致性组。




[[what-do-i-need-to-know-before-increasing-my-reserved-capacity-on-a-mirrored-pair-volume]]
== 在增加镜像对卷上的预留容量之前，我需要知道什么？

通常，当您收到镜像对的保留容量已满的警告时，应增加保留容量。您只能以 8 GiB 的增量增加保留容量。

对于异步镜像操作，保留容量通常为基本卷的 20%。如果存在以下一种或两种情况，请为保留容量选择更大的容量：

* 您打算将镜像对保留很长一段时间。
* 由于繁重的 I/O 活动，主卷上的大部分数据块将发生变化。使用历史性能数据或其他操作系统实用程序来帮助您确定主卷的典型 I/O 活动。


您可以通过执行以下操作之一来增加镜像对的保留容量：

* 通过选择菜单：Storage[Pools and Volumes Groups] 来调整镜像对卷的容量百分比，然后单击 *Reserved Capacity* 选项卡。
* 使用池或卷组上可用的可用容量创建新卷。
+
如果任何池或卷组上不存在可用容量，则可以将未配置的容量以未使用的驱动器的形式添加到池或卷组中。





[[why-cant-i-increase-reserved-capacity-with-my-requested-amount]]
== 为什么我无法按请求的数量增加预留容量？

您只能以 4 GiB 的增量增加保留容量。

查看以下指南：

* 您必须在池或卷组中具有足够的可用容量，以便在必要时可以对其进行扩展。
+
如果任何池或卷组上不存在可用容量，则可以将未分配的容量以未使用的驱动器的形式添加到池或卷组中。

* 池或卷组中的卷必须具有"最佳"状态，并且不得处于任何修改状态。
* 要用于增加容量的池或卷组中必须存在可用容量。


对于异步镜像操作，保留容量通常为基本卷的 20%。如果您认为基本卷将发生许多变化，或者存储对象的复制服务操作的估计预期寿命将非常长，请使用更高的百分比。



[[why-would-i-change-this-percentage]]
== 为什么要更改此百分比？

保留容量通常为快照操作的基本卷的 40%，异步镜像操作的基本卷的 20%。

通常这个容量就足够了。所需的容量因向基本卷写入 I/O 的频率和大小以及您打算使用存储对象的复制服务操作的时长而异。

一般来说，如果存在以下一种或两种情况，请为保留容量选择更大的百分比：

* 如果特定存储对象的复制服务操作的生命周期非常长。
* 如果由于大量 I/O 活动，基本卷上的大量数据块将发生变化。使用历史性能数据或其他操作系统实用程序来帮助您确定基本卷的典型 I/O 活动。




[[why-do-i-see-more-than-one-reserved-capacity-candidate]]
== 为什么我看到多个预留容量候选项？

如果池或卷组中有多个卷符合您为存储对象选择的容量百分比量，您将看到多个候选项。

您可以通过更改要在基本卷上保留用于复制服务操作的物理驱动器空间百分比来刷新推荐候选列表。根据您的选择显示最佳候选。



[[why-do-i-see-not-available-values-displayed-in-the-table]]
== 为什么在表中显示 Not Available 值？

当位于远程存储阵列上的数据不可显示时，该表列出了 Not Available 值。

要显示远程存储阵列数据，请从 Unified Manager 启动 System Manager。



[[why-dont-i-see-all-of-my-pools-and-volume-groups]]
== 为什么我没有看到所有的池和卷组？

为异步镜像对创建辅助卷时，系统将显示该异步镜像对的所有符合条件的池和卷组的列表。任何不符合使用条件的池或卷组都不会显示在该列表中。

池或卷组可能因以下任何原因而不符合条件。

* 池或卷组的安全功能不匹配。
* 池或卷组处于非最佳状态。
* 池或卷组的容量太小。




[[asynchronous-mirroring-why-dont-i-see-all-my-volumes]]
== 异步镜像 - 为什么我看不到所有卷？

为镜像对选择主卷时，列表会显示所有符合条件的卷。

不符合使用条件的任何卷都不会显示在该列表中。卷可能因以下任何原因不符合条件：

* 卷不是最佳的。
* 此卷已参与镜像关系。
* 对于精简卷，必须启用自动扩展。



NOTE: 对于 EF600 和 EF300 控制器，异步镜像对的主卷和辅助卷必须匹配相同的协议、托盘级别、段大小、安全类型和 RAID 级别。不符合条件的异步镜像对将不会出现在可用卷列表中。



[[asynchronous-mirroring-why-dont-i-see-all-the-volumes-on-the-remote-storage-array]]
== 异步镜像 - 为什么我看不到远程存储阵列上的所有卷？

在远程存储阵列上选择辅助卷时，列表会显示该镜像对的所有合格卷。

任何不符合使用条件的卷都不会显示在该列表中。由于以下任何原因，卷可能不符合条件：

* 卷不是最佳的。
* 此卷已参与镜像关系。
* 主卷和辅助卷之间的精简卷属性不匹配。
* 如果使用数据保障 (DA)，则主卷和辅助卷必须具有相同的 DA 设置。
+
** 如果主卷启用了 DA，则辅助卷必须启用 DA。
** 如果主卷未启用 DA，则辅助卷不得启用 DA。






[[why-would-i-update-my-remote-storage-arrays-ip-address]]
== 为什么要更新远程存储阵列的 IP 地址？

当 iSCSI 端口的 IP 地址更改且本地存储阵列无法与远程存储阵列通信时，可以更新远程存储阵列的 IP 地址。

当与 iSCSI 连接建立异步镜像关系时，本地和远程存储阵列都会在异步镜像配置中存储远程存储阵列的 IP 地址的记录。如果 iSCSI 端口的 IP 地址发生变化，则尝试使用该端口的远程存储阵列将遇到通信错误。

具有更改的 IP 地址的存储阵列向与镜像一致性组关联的每个远程存储阵列发送一条消息，这些镜像一致性组被配置为通过 iSCSI 连接进行镜像。接收此消息的存储阵列会自动更新其远程目标 IP 地址。

如果 IP 地址已更改的存储阵列无法将其阵列间消息发送到远程存储阵列，则系统会向您发送连接问题警报。使用"更新远程 IP 地址"选项与本地存储阵列重新建立连接。
