= 异步镜像在 SANtricity System Manager 中的工作原理
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
异步镜像可按需或按计划复制数据卷，从而最大限度地减少或避免可能因数据损坏或丢失而导致的停机时间。

异步镜像捕获特定时间点的主卷的状态，并仅复制自上次图像捕获以来发生变化的数据。可以立即更新主站点，并在带宽允许的情况下更新辅助站点。当网络资源可用时，信息将被缓存并稍后发送。

这种类型的镜像非常适合满足不间断操作的需求，一般来说，对于定期流程（如备份和存档），其网络效率要高得多。使用异步镜像的原因包括：

* 远程备份整合。
* 防范局部或广域灾害。
* 对实时数据的时间点映像进行应用程序开发和测试。




[[asynchronous-mirroring-session]]
== 异步镜像会话

异步镜像捕获特定时间点的主卷的状态，并仅复制自上次图像捕获以来发生变化的数据。异步镜像允许立即更新主站点，并在带宽允许的情况下更新辅助站点。信息将被缓存并在网络资源可用时稍后发送。

活动异步镜像会话中有四个主要步骤。

image::../media/sam-1130-dwg-async-mirroring-session.gif[异步镜像会话]

. 写入操作首先发生在主卷的存储阵列上。
. 此操作的状态将返回给主机。
. 记录并跟踪主卷上的所有更改。
. 所有更改都作为后台进程发送到辅助卷的存储阵列。


根据定义的同步间隔重复这些步骤，或者如果没有定义间隔，则可以手动重复这些步骤。

异步镜像仅以设置的时间间隔将数据传输到远程站点，因此本地 I/O 不会受到慢速网络连接的影响。由于此传输未绑定到本地 I/O，因此不会影响应用程序性能。因此，异步镜像可以使用较慢的连接（如 iSCSI），并在本地和远程存储系统之间运行较长的距离。

存储阵列必须具有 7.84 的最低固件版本。（它们可以各自运行不同的 OS 版本。）



[[mirror-consistency-groups-and-mirrored-pairs]]
== 镜像一致性组和镜像对

您创建镜像一致性组，以建立本地存储阵列和远程存储阵列之间的镜像关系。异步镜像关系由一个镜像对组成：一个存储阵列上的主卷和另一个存储阵列上的辅助卷。

包含主卷的存储阵列通常位于主站点，并为活动主机提供服务。包含辅助卷的存储阵列通常位于辅助站点，并保存数据的副本。辅助卷通常包含数据的备份副本，用于灾难恢复。



[[synchronization-settings]]
== 同步设置

创建镜像对时，还可以定义镜像对在通信中断后用于完成重新同步操作的同步优先级和重新同步策略。

创建镜像一致性组时，还要为组中的所有镜像对定义同步优先级和重新同步策略。镜像对使用同步优先级和重新同步策略在通信中断后完成重新同步操作。

当主卷的存储阵列无法将数据写入辅助卷时，镜像对中的主卷和辅助卷可能会变得不同步。这种情况可能是由以下问题引起的：

* 本地和远程存储阵列之间的网络问题。
* 出现故障的辅助卷。
* 正在镜像对上手动挂起同步。
* 镜像组角色冲突。


您可以手动或自动同步远程存储阵列上的数据。



[[reserved-capacity-and-asynchronous-mirroring]]
== 保留容量和异步镜像

当未发生同步时，保留容量用于跟踪主卷和辅助卷之间的差异。它还跟踪每个镜像对的同步统计信息。

镜像对中的每个卷都需要其自己的保留容量。



[[configuration-and-management]]
== 配置和管理

要启用和配置两个阵列之间的镜像，必须使用 Unified Manager 界面。启用镜像后，您可以在 System Manager 中管理镜像对和同步设置。
