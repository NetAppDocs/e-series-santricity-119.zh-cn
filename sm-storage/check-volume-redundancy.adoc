= 在 SANtricity System Manager 中检查卷冗余
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
在技术支持的指导下或根据 Recovery Guru 的指示，您可以检查池或卷组中卷上的冗余，以确定该卷上的数据是否一致。

冗余数据用于在池或卷组中的一个驱动器发生故障时快速重建替换驱动器上的信息。

.开始之前
* 此池或卷组的状态必须为 Optimal。
* 池或卷组必须没有正在进行的卷修改操作。
* 您可以在除 RAID 0 以外的任何 RAID 级别上检查冗余，因为 RAID 0 没有数据冗余。


[NOTE]
====
仅在 Recovery Guru 指示并在技术支持指导下检查卷冗余。

====
.关于此任务
一次只能对一个池或卷组执行此检查。卷冗余检查执行以下操作：

* 扫描 RAID 3 卷、RAID 5 卷或 RAID 6 卷中的数据块，并检查每个块的冗余信息。（只能使用命令行界面将 RAID 3 分配给卷组。）
* 比较 RAID 1 镜像驱动器上的数据块。
* 如果控制器固件确定数据不一致，则返回冗余错误。


[NOTE]
====
立即对同一个池或卷组运行冗余检查可能会导致错误。要避免此问题，请等待一到两分钟，然后再对同一个池或卷组运行另一个冗余检查。

====
.步骤
. 选择菜单：Storage[Pools & Volume Groups]。
. 选择菜单：Uncommon Tasks[Check volume redundancy]。
+
此时将显示"检查冗余"对话框。

. 选择要检查的卷，然后键入  `check` 以确认要执行此操作。
. 单击 *Check*。
+
检查卷冗余操作开始。从对话框中的表顶端开始，按顺序扫描池或卷组中的卷。在扫描每个卷时，将执行以下操作：

+
** 卷在卷表中被选中。
** 冗余检查的状态显示在 *Status* 列中。
** 检查在遇到任何介质或奇偶校验错误时停止，然后报告该错误。
+
.有关冗余检查状态的更多信息

====

 a|

 a|

 a|

 a|

 a| 
奇偶校验不是数据给定部分的应有结果。奇偶校验错误可能很严重，并可能导致数据永久丢失。

|===
====


. 检查池或卷组中的最后一个卷后，单击 *Done*。
