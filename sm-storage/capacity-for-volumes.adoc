= 如何在 SANtricity System Manager 中为卷分配容量
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
存储阵列中的驱动器为数据提供物理存储容量。在开始存储数据之前，必须将分配的容量配置为称为池或卷组的逻辑组件。您可以使用这些存储对象在存储阵列上配置、存储、维护和保留数据。



== 使用容量创建和扩展卷

您可以从池或卷组中的未分配容量或可用容量创建卷。

* 使用未分配的容量创建卷时，可以同时创建池或卷组和卷。
* 从可用容量创建卷时，您是在现有池或卷组上创建一个附加卷。


扩展卷容量后，您必须手动增加文件系统大小以匹配。如何执行此操作取决于您正在使用的文件系统。有关详细信息，请参阅您的主机操作系统文档。



== 厚卷和薄卷的容量类型

您可以创建厚卷或精简卷。对于厚卷，报告容量和分配容量相同，但对于精简卷则不同。

* 对于厚卷，报告的卷容量等于分配的物理存储容量。必须存在整个物理存储容量。物理分配的空间等于向主机报告的空间。
+
您通常会将厚卷的报告容量设置为您认为该卷将增长到的最大容量。厚卷为您的应用程序提供高性能和可预测的性能，主要是因为所有用户容量都是在创建时保留和分配的。

* 对于精简卷，报告的容量是报告给主机的容量，而分配的容量是当前分配用于写入数据的驱动器空间量。
+
报告的容量可能大于存储阵列上分配的容量。可以调整瘦卷大小以适应增长，而无需考虑当前可用的资产。



[NOTE]
====
SANtricity System Manager 不提供创建精简卷的选项。如果要创建精简卷，请使用命令行界面 (CLI)。

====


== 厚卷的容量限制

厚卷的最小容量为 1 MiB，最大容量由池或卷组中驱动器的数量和容量决定。

在增加厚卷的报告容量时，请记住以下准则：

* 最多可以指定三个小数位（例如 65.375 GiB）。
* 容量需要小于（或等于）卷组中的最大可用容量。
+
创建卷时，会为动态段大小 (DSS) 迁移预分配一些额外容量。DSS 迁移是软件的一项功能，允许您更改卷的段大小。

* 某些主机操作系统支持大于 2 TiB 的卷（报告的最大容量由主机操作系统确定）。实际上，某些主机操作系统支持高达 128 TiB 的卷。请参见主机操作系统文档了解其他详细信息。




== 精简卷的容量限制

您可以创建具有较大报告容量和相对较小分配容量的精简卷，这有利于提高存储利用率和效率。精简卷可以帮助简化存储管理，因为分配的容量可以随着应用程序需求的变化而增加，而不会中断应用程序，从而实现更好的存储利用率。

除了报告的容量和分配的容量外，精简卷还包含已写入容量。已写入容量是从为精简卷分配的保留容量中已写入的容量量。

下表列出了精简卷的容量限制。

[cols="3*"]
|===
| 容量类型 | 大小上限 | 最小大小 


 a| 
已报告
 a| 
32 MiB
 a| 
256 TiB



 a| 
已分配
 a| 
4 MiB
 a| 
64 TiB

|===
对于精简卷，如果已达到 256 TiB 的最大报告容量，则无法增加其容量。确保将精简卷的预留容量设置为大于最大报告容量的大小。

系统会根据分配的容量限制自动扩展分配的容量。分配的容量限制允许您将精简卷的自动增长限制在报告的容量以下。当写入数据量接近分配容量时，可以更改分配容量限制。

要更改分配的容量限制，请选择菜单：Storage[Volumes > Thin Volume Monitoring tab > Change Limit]。

由于 System Manager 在创建精简卷时未分配全部容量，因此池中可能存在可用容量不足的情况。空间不足可能会阻止对池的写入，这不仅适用于精简卷，也适用于需要池容量的其他操作（例如快照映像或快照卷）。但是，您仍然可以从池中执行读取操作。如果发生这种情况，您将收到警报阈值警告。
