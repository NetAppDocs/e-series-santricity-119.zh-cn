= 可以对 SANtricity System Manager 中的卷执行的操作
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
您可以在卷上执行许多不同的操作：增加容量、删除、复制、初始化、重新分发、更改所有权、更改缓存设置以及更改媒体扫描设置。



== 增加容量

您可以通过两种方式扩展卷的容量：

* 使用池或卷组中的可用容量。
+
您可以通过选择菜单：Storage[Pools and Volume Groups > Add Capacity] 向卷添加容量。

* 将未分配的容量（以未使用驱动器的形式）添加到卷的池或卷组。池或卷组中不存在可用容量时使用此选项。
+
您可以通过选择菜单：Storage[Pools and Volume Groups > Add Capacity] 将未分配的容量添加到池或卷组。

+
如果池或卷组中没有可用容量，则无法增加卷的容量。必须首先增加池或卷组的大小或删除未使用的卷。



扩展卷容量后，您必须手动增加文件系统大小以匹配。如何执行此操作取决于您正在使用的文件系统。有关详细信息，请参阅您的主机操作系统文档。



== 删除

通常，如果卷是使用错误的参数或容量创建的，不再满足存储配置需求，或者是备份或应用程序测试不再需要的快照映像，则会删除卷。删除卷会增加池或卷组中的可用容量。

删除卷会导致这些卷上的所有数据丢失。删除卷还将删除所有关联的快照映像、计划和快照卷，并删除所有镜像关系。



== 复制

复制卷时，需要在同一存储阵列上创建两个独立卷（源卷和目标卷）的时间点副本。您可以通过选择菜单来复制卷：Storage[Volumes > Copy Services > Copy volume]。



== 初始化

初始化卷会擦除卷中的所有数据。卷在首次创建时会自动初始化。但是，Recovery Guru 可能会建议您手动初始化卷以从某些故障状态中恢复。初始化卷时，该卷将保留其 WWN、主机分配、分配的容量和保留的容量设置。它还保留相同的 Data Assurance (DA) 设置和安全设置。

您可以通过选择菜单：Storage[Volumes > More > Initialize volumes] 来初始化卷。



== 重新分配

重新分配卷以将卷移回其首选控制器所有者。通常，当主机和存储阵列之间的数据路径出现问题时，多路径驱动程序会从其首选控制器所有者处移动卷。

大多数主机多路径驱动程序会尝试访问其首选控制器所有者路径上的每个卷。但是，如果此首选路径不可用，主机上的多路径驱动程序会故障转移到备用路径。此故障转移可能会导致卷所有权更改为备用控制器。解决导致故障转移的条件后，某些主机可能会自动将卷所有权移回首选控制器所有者，但在某些情况下，可能需要手动重新分配卷。

您可以通过选择菜单：Storage[Volumes > More > Redistribute volumes] 来重新分配卷。



== 更改卷所有权

更改卷的所有权会更改卷的首选控制器所有权。卷的首选控制器所有者列在菜单下：Storage[Volumes > View/Edit Settings > Advanced tab]。

您可以通过选择菜单：Storage[Volumes > More > Change ownership] 来更改卷的所有权。



=== 镜像和卷所有权

如果镜像对的主卷由控制器 A 所有，则辅助卷也将由远程存储阵列的控制器 A 所有。更改主卷的所有者将自动更改辅助卷的所有者，以确保两个卷由同一个控制器所有。主端的当前所有权变更会自动传播到辅助端的相应当前所有权变更。

如果镜像一致性组包含本地辅助卷，并且控制器所有权发生更改，则辅助卷会在第一次写入操作时自动传输回其原始控制器所有者。您无法使用 *Change ownership* 选项更改辅助卷的控制器所有权。



=== 复制卷和卷所有权

在复制卷操作期间，同一控制器必须同时拥有源卷和目标卷。有时，当复制卷操作启动时，两个卷没有相同的首选控制器。因此，目标卷的所有权将自动转移到源卷的首选控制器。当卷副本完成或停止时，目标卷的所有权将恢复到其首选控制器。

如果在复制卷操作期间更改了源卷的所有权，则还会更改目标卷的所有权。在某些操作系统环境中，可能需要在使用 I/O 路径之前重新配置多路径主机驱动程序。（某些多路径驱动程序需要进行编辑才能识别 I/O 路径。有关详细信息，请参阅您的驱动程序文档。）



== 更改缓存设置

缓存内存是控制器上临时易失性存储 (RAM) 的区域，其访问时间快于驱动器介质。如果使用缓存内存，由于以下原因，您可以提高整体 I/O 性能：

* 从主机请求读取的数据可能已经存在于先前操作的缓存中，因此无需驱动器访问。
* 写入数据最初会写入缓存，从而使应用程序可以继续，而不是等待数据写入驱动器。


选择菜单：Storage[Volumes > More > Change cache settings] 以更改以下缓存设置：

* *读写缓存* -- 读缓存是存储已从驱动器读取的数据的缓冲区。读取操作的数据可能已经存在于先前操作的缓存中，因此无需访问驱动器。数据保留在读缓存中，直到刷新为止。
+
写缓存是存储来自主机尚未写入驱动器的数据的缓冲区。数据将保留在写缓存中，直到写入驱动器。写缓存可以提高 I/O 性能。

* *带镜像的写缓存* -- 当写入一个控制器的缓存内存的数据也写入另一个控制器的缓存内存时，将发生带镜像的写缓存。因此，如果一个控制器发生故障，另一个控制器可以完成所有未完成的写入操作。仅当写缓存已启用且存在两个控制器时，写缓存镜像才可用。使用镜像进行写缓存是创建卷时的默认设置。
* *不带电池的写缓存* -- 不带电池的写缓存设置允许写缓存继续，即使电池丢失、故障、完全放电或未完全充电。通常不建议选择没有电池的写缓存，因为如果断电，数据可能会丢失。通常，控制器会暂时关闭写缓存，直到电池充电或更换故障电池。
+
此设置仅在启用写缓存时可用。此设置不适用于精简卷。

* *动态读缓存预取* -- 动态缓存读取预取允许控制器在将数据块从驱动器读取到缓存时将额外的顺序数据块复制到缓存中。这种缓存增加了将来从缓存中填充数据请求的可能性。动态缓存读取预取对于使用顺序 I/O 的多媒体应用程序非常重要。预取到缓存的数据速率和数量是根据主机读取的速率和请求大小自行调整的。随机访问不会导致数据被预取到缓存中。禁用读缓存时，此功能不适用。
+
对于精简卷，动态缓存读取预取始终被禁用且无法更改。





== 更改媒体扫描设置

介质扫描检测并修复应用程序不经常读取的磁盘块上的介质错误。如果池或卷组中的其他驱动器发生故障，此扫描可以防止发生数据丢失，因为故障驱动器的数据是使用冗余信息和池或卷组中其他驱动器的数据重建的。

介质扫描根据要扫描的容量和扫描持续时间以恒定速率连续运行。后台扫描可能会被更高优先级的后台任务（例如重建）暂时挂起，但将以相同的恒定速率恢复。

您可以通过选择菜单：Storage[Volumes > More > Change media scan settings] 来启用和设置介质扫描运行的持续时间。

仅当为存储阵列和该卷启用了媒体扫描选项时，才会扫描卷。如果该卷也启用了冗余检查，则将检查卷中的冗余信息是否与数据一致，前提是该卷具有冗余。创建每个卷时，默认情况下会启用带冗余检查的媒体扫描。

如果在扫描过程中遇到不可恢复的介质错误，则将使用冗余信息（如果可用）修复数据。例如，冗余信息在最佳 RAID 5 卷中可用，或者在最佳 RAID 6 卷中可用，或者仅有一个驱动器发生故障。如果无法使用冗余信息修复不可恢复的错误，数据块将被添加到不可读扇区日志中。可更正和不可更正的介质错误都会报告到事件日志中。

如果冗余检查发现数据与冗余信息不一致，则将其报告给事件日志。
