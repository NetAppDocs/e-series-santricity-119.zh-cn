= 工作负载在 SANtricity 软件中的工作原理
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
创建卷时，选择一个工作负载以自定义特定应用程序的存储阵列配置。

工作负载是支持应用程序的存储对象。可以为每个应用程序定义一个或多个工作负载或实例。对于某些应用程序，系统将工作负载配置为包含具有类似底层卷特征的卷。这些卷特性是根据工作负载支持的应用程序类型进行优化的。例如，如果创建支持 Microsoft SQL Server 应用程序的工作负载，然后为该工作负载创建卷，则会优化基础卷特征以支持 Microsoft SQL Server。

在创建卷期间，系统会提示您回答有关工作负载使用的问题。例如，如果要为 Microsoft Exchange 创建卷，系统会询问您需要多少个邮箱、平均邮箱容量要求以及所需的数据库副本数。系统使用此信息为您创建最佳卷配置，可以根据需要对其进行编辑。或者，您可以在卷创建顺序中跳过此步骤。



[[types-of-workloads]]
== 工作负载类型

您可以创建两种类型的工作负载：Application-specific 和 Other。

* *特定于应用程序*。使用特定于应用程序的工作负载创建卷时，系统可能会推荐优化的卷配置，以最大限度地减少应用程序工作负载 I/O 与来自应用程序实例的其他流量之间的竞争。对于为以下应用程序类型创建的工作负载，会自动推荐和优化 I/O 类型、段大小、控制器所有权以及读取和写入缓存等卷特征。
+
** Microsoft® SQL Server™
** Microsoft® Exchange Server™
** 视频监控应用程序
** VMware ESXi™（用于与 Virtual Machine File System 配合使用的卷）
+
您可以使用 Add/Edit Volumes 对话框查看推荐的卷配置并编辑、添加或删除系统推荐的卷和特征。



* *其他* （或不支持特定卷创建的应用程序）。其他工作负载使用的卷配置必须在您要创建未与特定应用程序关联的工作负载时手动指定，或者如果系统未针对您要在存储阵列上使用的应用程序进行内置优化。您必须使用"添加/编辑卷"对话框手动指定卷配置。




[[application-and-workload-views]]
== 应用程序和工作负载视图

要查看应用程序和工作负载，请启动 SANtricity System Manager。从该界面，您可以通过几种不同的方式查看与特定于应用程序的工作负载相关的信息：

* 您可以选择卷图块中的 *Applications & Workloads* 选项卡，以查看按工作负载和工作负载关联的应用程序类型分组的存储阵列的卷。
* 您可以选择性能图块中的*应用程序和工作负载*选项卡，以查看逻辑对象的性能指标（延迟、IOPS 和 MB）。对象按应用程序和相关工作负载分组。通过定期收集此性能数据，您可以建立基线测量并分析趋势，这有助于调查与 I/O 性能相关的问题。
