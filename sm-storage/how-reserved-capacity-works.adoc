= SANtricity 软件中保留容量的工作原理
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
为卷提供复制服务操作（如快照或异步镜像操作）时，将自动创建保留容量。

保留容量的目的是在出现问题时存储这些卷上的数据更改。与卷一样，保留容量是从池或卷组创建的。



== 复制使用预留容量的服务对象

保留容量是这些复制服务对象使用的底层存储机制：

* Snapshot 组
* 读/写快照卷
* 一致性组成员卷
* 镜像对卷


创建或扩展这些复制服务对象时，必须从池或卷组创建新的保留容量。保留容量通常是快照操作的基本卷的 40% 和异步镜像操作的基本卷的 20%。但是，保留容量会根据对原始数据的更改次数而有所不同。



== 精简卷和预留容量

对于精简卷，如果已达到 256 TiB 的最大报告容量，则无法增加其容量。确保将精简卷的预留容量设置为大于最大报告容量的大小。（精简卷始终是精简配置的，这意味着在将数据写入卷时会分配容量。）

如果使用池中的精简卷创建保留容量，请查看有关保留容量的以下操作和结果：

* 如果精简卷的保留容量失败，则精简卷本身不会自动转换为"失败"状态。但是，由于精简卷上的所有 I/O 操作都需要访问保留容量卷，因此 I/O 操作将始终导致将检查条件返回给请求主机。如果保留容量卷的根本问题可以解决，则保留容量卷将返回到"最佳"状态，并且精简卷将再次发挥作用。
* 如果使用现有精简卷来完成异步镜像对，则会使用新的保留容量卷重新初始化该精简卷。在初始同步过程中，只有在主端调配的块才会被传输。




== 容量警报

复制服务对象具有可配置的容量警告和警报阈值，以及保留容量已满时的可配置响应。

当复制服务对象卷的保留容量接近填充点时，向用户发出警报。默认情况下，当保留容量卷已满 75% 时会发出此警报；但是，您可以根据需要向上或向下调整此警报点。如果您收到此警报，则可以增加当时保留容量卷的容量。在这方面，每个复制服务对象都可以独立配置。



== 孤立的预留容量卷

孤立的保留容量卷是一个不再存储用于复制服务操作的数据的卷，因为其关联的复制服务对象已被删除。当复制服务对象被删除时，其保留容量卷也应该被删除。但是，保留容量卷无法删除。

由于孤立的保留容量卷未被任何主机访问，因此它们是回收的候选卷。手动删除孤立的保留容量卷，以便您可以将其容量用于其他操作。

System Manager 会在主页的通知区域显示"回收未使用的容量"消息，提醒您孤立的保留容量卷。您可以单击*回收未使用的容量*以显示"回收未使用的容量"对话框，您可以在其中删除孤立的保留容量卷。



== 预留容量的特点

* 在卷创建期间，需要考虑分配给保留容量的容量，以保留足够的可用容量。
* 保留容量可以小于基本卷（最小大小为 8 MiB）。
* 一些空间由元数据消耗，但它非常小（192 KiB），因此在确定保留容量卷的大小时不需要考虑它。
* 保留容量不能从主机直接读取或写入。
* 每个读/写快照卷、快照组、一致性组成员卷和镜像对卷都存在保留容量。
