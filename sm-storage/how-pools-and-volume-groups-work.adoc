= 池和卷组在 SANtricity 软件中的工作方式
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
要配置存储，请创建一个池或卷组，其中将包含要在存储阵列中使用的硬盘驱动器 (HDD) 或固态硬盘 (SSD) 驱动器。

物理硬件配置到逻辑组件中，以便可以组织并轻松检索数据。支持两种类型的分组：

* 池
* RAID 卷组


池和卷组是存储阵列中的顶级存储单元：它们将驱动器的容量划分为可管理的部分。在这些逻辑分区内是存储数据的单个卷或 LUN。下图说明了这个概念。

image::../media/sam1130-dwg-volumes-drive-structure-pools-and-volume-groups.gif[池和卷组结构]

^1^ 主机 LUN；^2^ 卷；^3^ 卷组或池；^4^ HDD 或 SSD 驱动器

部署存储系统时，第一步是向各种主机提供可用驱动器容量：

* 创建具有足够容量的池或卷组
* 将满足性能要求所需的驱动器数量添加到池或卷组
* 选择所需的 RAID 保护级别（如果使用卷组）以满足特定的业务要求


您可以在同一存储系统上拥有池或卷组，但驱动器不能属于多个池或卷组。然后使用池或卷组上的空间创建呈现给主机用于 I/O 的卷。



[[pools]]
== 池

池旨在将物理硬盘驱动器聚合到大型存储空间中，并为其提供增强的 RAID 保护。池根据分配给池的驱动器总数创建多个虚拟 RAID 集，并在所有参与的驱动器之间均匀分布数据。如果驱动器丢失或添加，System Manager 会在所有活动驱动器上动态重新平衡数据。

池充当另一个 RAID 级别，虚拟化底层 RAID 架构，以在执行重建、驱动器扩展和处理驱动器丢失等任务时优化性能和灵活性。System Manager 在 8+2 配置（八个数据磁盘加两个奇偶校验磁盘）中自动将 RAID 级别设置为 6。



[[drive-matching]]
=== 驱动器匹配

您可以从 HDD 或 SSD 中选择在池中使用；但是，与卷组一样，池中的所有驱动器都必须使用相同的技术。控制器会自动选择要包含的驱动器，因此您必须确保您有足够数量的驱动器用于您选择的技术。



[[managing-failed-drives]]
=== 管理故障驱动器

池的最小容量为 11 个驱动器；但是，在发生驱动器故障时，会为备用容量保留一个驱动器的容量。这种备用容量称为"`preservation capacity`"。

创建池时，会保留一定的容量以备紧急使用。此容量以 System Manager 中的多个驱动器表示，但实际实施分布在整个驱动器池中。保留的默认容量量基于池中的驱动器数量。

创建池后，您可以将保留容量值更改为更多或更少的容量，甚至将其设置为无保留容量（0 个驱动器的价值）。可保留的最大容量（以驱动器数量表示）为 10，但根据池中的驱动器总数，可用容量可能会更少。



[[volume-groups]]
== 卷组

卷组定义如何在存储系统中将容量分配给卷。磁盘驱动器被组织成 RAID 组，卷驻留在 RAID 组中的驱动器上。因此，卷组配置设置确定哪些驱动器属于该组以及使用什么 RAID 级别。

创建卷组时，控制器会自动选择要包含在该组中的驱动器。您必须手动选择该组的 RAID 级别。卷组的容量是您选择的驱动器总数乘以其容量。



[[drive-matching]]
=== 驱动器匹配

您必须匹配卷组中驱动器的大小和性能。如果卷组中有较小和较大的驱动器，则所有驱动器都将被识别为最小容量大小。如果卷组中有较慢和较快的驱动器，则会以最慢的速度识别所有驱动器。这些因素会影响存储系统的性能和整体容量。

您不能混合使用不同的驱动器技术（HDD 和 SSD 驱动器）。RAID 3、5 和 6 限制为最多 30 个驱动器。RAID 1 和 RAID 10 使用镜像，因此这些卷组必须具有偶数个磁盘。



[[managing-failed-drives]]
=== 管理故障驱动器

卷组使用热备盘驱动器作为备用，以防卷组中包含的 RAID 1/10、RAID 3、RAID 5 或 RAID 6 卷中的驱动器出现故障。热备盘驱动器不包含任何数据，并为存储阵列添加另一个级别的冗余。

如果存储阵列中的驱动器出现故障，热备盘驱动器将自动替换出现故障的驱动器，而无需进行物理交换。如果热备盘驱动器在驱动器发生故障时可用，则控制器使用冗余数据将数据从发生故障的驱动器重建到热备盘驱动器。
