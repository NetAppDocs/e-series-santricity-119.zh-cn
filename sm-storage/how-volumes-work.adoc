= SANtricity 软件中卷的工作原理
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
卷是管理和组织存储阵列上存储空间的数据容器。

您可以从存储阵列上的可用存储容量创建卷，并轻松组织和使用系统资源。这个概念类似于使用计算机上的文件夹/目录来组织文件，以便轻松快速地访问。

卷是主机唯一可见的数据层。在 SAN 环境中，卷映射到逻辑单元编号 (LUN)，这些逻辑单元编号对主机可见。LUN 保存可使用存储阵列支持的一个或多个主机访问协议（包括 FC、iSCSI 和 SAS）访问的用户数据。



[[volume-types-you-can-create-from-pools-and-volume-groups]]
== 可以从池和卷组创建的卷类型

卷从池或卷组中提取其容量。您可以从存储阵列上存在的池或卷组创建以下类型的卷。

* *从池* -- 您可以从池中创建卷，作为_完全置备的（厚）卷_或_精简置备的（薄）卷_。
+
[NOTE]
====
System Manager 界面不提供创建精简卷的选项。如果要创建精简卷，请使用命令行界面 (CLI)。

====
* *从卷组* -- 您只能将卷组中的卷创建为_完全置备（厚）卷_。


胖卷和瘦卷以不同的方式从存储阵列中获取容量：

* 在创建卷时分配厚卷的容量。
* 精简卷的容量在写入卷时作为数据进行分配。


精简配置有助于避免浪费分配的容量，并可以为企业节省前期存储成本。但是，完全配置的优点是延迟更少，因为在创建厚卷时会一次分配所有存储。

[NOTE]
====
EF600/EF600C 和 EF300/EF300C 存储系统不支持精简配置。

====


[[characteristics-of-volumes]]
== 卷的特征

池或卷组中的每个卷都可以根据其中存储的数据类型具有其各自的特征。其中一些特征包括：

* *段大小* -- 段是在存储阵列移动到条带中的下一个驱动器（RAID 组）之前以千字节 (KiB) 为单位存储在驱动器上的数据量。段大小等于或小于卷组的容量。池的段大小是固定的，无法更改。
* *容量* -- 您可以从池或卷组中的可用容量创建卷。在创建卷之前，池或卷组必须已存在，并且必须具有足够的可用容量才能创建卷。
* *控制器所有权* -- 所有存储阵列都可以有一个或两个控制器。在单控制器阵列上，卷的工作负载由单个控制器管理。在双控制器阵列上，卷将具有"`拥有`"卷的首选控制器（A 或 B）。在双控制器配置中，使用自动负载平衡功能自动调整卷所有权，以便在工作负载跨控制器转移时纠正任何负载平衡问题。自动负载平衡提供自动 I/O 工作负载平衡，并确保来自主机的传入 I/O 流量在两个控制器之间进行动态管理和平衡。
* *卷分配* -- 您可以在创建卷时或稍后向主机授予对卷的访问权限。所有主机访问均通过逻辑单元号 (LUN) 进行管理。主机检测到分配给卷的 LUN。如果要将卷分配给多个主机，请使用群集软件确保卷对所有主机可用。
+
主机类型可以对主机可以访问的卷数进行特定限制。在创建供特定主机使用的卷时，请记住此限制。

* *描述性名称* -- 您可以随心所欲地命名卷，但我们建议您使名称具有描述性。


在创建卷期间，为每个卷分配容量，并为其分配名称、段大小（仅限卷组）、控制器所有权和卷到主机的分配。根据需要，卷数据会自动在控制器之间进行负载平衡。
