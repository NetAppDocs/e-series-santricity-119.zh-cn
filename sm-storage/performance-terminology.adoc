= 了解 SANtricity 软件中的性能术语
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
了解性能条款如何适用于您的存储阵列。

[cols="25h,~"]
|===
| 术语 | 说明 


 a| 
应用程序
 a| 
应用程序是一种软件程序，例如 SQL 或 Exchange。



 a| 
CPU
 a| 
CPU 是"中央处理器"的缩写。CPU 表示存储阵列正在使用的处理容量的百分比。



 a| 
主机
 a| 
主机是向存储阵列上的卷发送 I/O 的服务器。



 a| 
IOPS
 a| 
IOPS 代表每秒的输入/输出操作。



 a| 
延迟
 a| 
延迟是请求（例如读取或写入命令）与来自主机或存储阵列的响应之间的时间间隔。



 a| 
LUN
 a| 
逻辑单元号 (LUN) 是分配给主机用于访问卷的地址空间的编号。此卷以 LUN 的形式作为容量呈现给主机。

每个主机都有自己的 LUN 地址空间。因此，不同的主机可以使用相同的 LUN 来访问不同的卷。



 a| 
MiB
 a| 
MiB 是 mebibyte（百万二进制字节）的缩写。1 MiB 为 2，或 1,048,576 字节。与 MB 进行比较，MB 表示基数为 10 的值。1 MB 等于 1,000,000 字节。



 a| 
对象
 a| 
对象是任何逻辑或物理存储组件。

逻辑对象包括卷组、池和卷。物理对象包括存储阵列、阵列控制器、主机和驱动器。



 a| 
池
 a| 
池是逻辑上分组的一组驱动器。您可以使用池创建一个或多个可供主机访问的卷。（您可以从池或卷组创建卷。）



 a| 
读取
 a| 
Read 是"读取操作"的缩写，在主机请求存储阵列中的数据时发生。



 a| 
卷
 a| 
卷是应用程序、数据库和文件系统存储数据的容器。它是为主机创建的逻辑组件，用于访问存储阵列上的存储。

卷是根据池或卷组中的可用容量创建的。卷具有定义的容量。虽然卷可能由多个驱动器组成，但卷在主机上显示为一个逻辑组件。



 a| 
卷名称
 a| 
卷名是创建卷时分配给卷的字符串。您可以接受默认名称，也可以提供一个更具描述性的名称来指示卷中存储的数据类型。



 a| 
卷组
 a| 
卷组是具有共享特征的卷的容器。卷组具有定义的容量和 RAID 级别。您可以使用卷组创建一个或多个可供主机访问的卷。（您可以从卷组或池创建卷。）



 a| 
工作负载
 a| 
工作负载是支持应用程序的存储对象。可以为每个应用程序定义一个或多个工作负载或实例。对于某些应用程序，系统将工作负载配置为包含具有类似底层卷特征的卷。这些卷特性是根据工作负载支持的应用程序类型进行优化的。例如，如果创建支持 Microsoft SQL Server 应用程序的工作负载，然后为该工作负载创建卷，则会优化基础卷特征以支持 Microsoft SQL Server。



 a| 
写入
 a| 
写入是"写入操作"的缩写，即数据从主机发送到阵列进行存储时的操作。

|===
