= 了解 SANtricity 软件中拷贝卷操作的类型
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
您可以执行 _offline_ Copy Volume 操作或 _online_ Copy Volume 操作。脱机操作从源卷读取数据并将其复制到目标卷。联机操作使用快照卷作为源，并将其数据复制到目标卷。

为了确保数据完整性，在任何一种类型的拷贝卷操作期间，目标卷的所有 I/O 活动都将暂停。此暂停是因为在过程完成之前，目标卷上的数据状态不一致。

下面将介绍离线和在线 Copy Volume 操作。



[[offline-copy-volume-operation]]
== 离线拷贝卷操作

脱机拷贝卷关系位于源卷和目标卷之间。脱机副本从源卷读取数据并将其复制到目标卷，同时暂停对正在进行复制的源卷的所有更新。将暂停对源卷的所有更新，以防止在目标卷上创建按时间顺序排列的不一致。

[cols="25h,~"]
|===
2+| 有关离线复制操作的注意事项 


 a| 
读取和写入请求
 a| 
* 参与脱机拷贝的源卷可用于只读 I/O 活动，而 Copy Volume 操作的状态为"正在进行"或"待处理"。
* 允许在脱机复制完成后写入请求。
* 为防止出现写保护错误消息，请勿访问状态为"正在进行"的参与 Copy Volume 操作的源卷。




 a| 
日志文件系统
 a| 
* 如果已使用日志文件系统格式化源卷，则任何向源卷发出读取请求的尝试都可能被存储阵列控制器拒绝，并可能出现错误消息。
* 日志文件系统驱动程序在尝试发出读取请求之前发出写入请求。控制器拒绝写入请求，并且由于被拒绝的写入请求，可能无法发出读取请求。此情况可能导致出现错误消息，指示源卷受写保护。
* 为防止出现此问题，请勿尝试在 Copy Volume 操作的状态为 In Progress 时访问参与脱机副本的源卷。


|===


[[online-copy-volume-operation]]
== 联机复制卷操作

联机 Copy Volume 关系是快照卷和目标卷之间的关系。您可以在源卷联机并可用于数据写入时启动 Copy Volume 操作。此功能通过创建卷的快照并将快照用作副本的实际源卷来实现。

当您启动源卷的复制卷操作时，System Manager 会创建基本卷的快照映像以及基本卷的快照映像与目标卷之间的复制关系。将快照映像用作源卷允许存储阵列在复制过程中继续写入源卷。

在联机复制操作期间，由于写入时复制过程，会遇到性能影响。在线复制完成后，将恢复基本卷性能。

[cols="25h,~"]
|===
2+| 有关在线复制操作的注意事项 


 a| 
可以使用什么类型的卷？
 a| 
* 为其创建时间点映像的卷称为基本卷，并且必须是存储阵列上的标准卷或精简卷。
* 目标卷可以是卷组中的标准卷，也可以是池中的标准卷。目标卷不能是快照组中的精简卷或基本卷。
* 您可以使用联机复制卷功能将数据从精简卷复制到驻留在同一存储阵列中的池中的标准卷。但是，您不能使用复制卷功能将数据从标准卷复制到精简卷。




 a| 
基本卷性能
 a| 
* 如果用作复制源的快照卷处于活动状态，则由于写入时复制操作，基本卷性能会降低。复制完成后，将禁用快照，并恢复基本卷性能。虽然快照被禁用，但保留的容量卷和复制关系保持不变。




 a| 
已创建卷的类型
 a| 
* 快照卷和保留容量卷是在联机复制操作期间创建的。
* 快照卷不是包含数据的实际卷；相反，它是对特定时间卷上包含的数据的引用。
* 对于拍摄的每个快照，都会创建一个保留容量卷来保存快照的数据。保留容量卷仅用于管理快照映像。




 a| 
预留容量卷
 a| 
* 在修改源卷上的数据块之前，要修改的块的内容将被复制到保留容量卷以供保存。
* 由于保留容量卷将原始数据的副本存储在这些数据块中，因此对这些数据块的进一步更改仅写入源卷。
* 联机复制操作使用的磁盘空间少于完整物理副本，因为存储在保留容量卷中的唯一数据块是自 snapshot 时间以来已更改的数据块。
