= 了解 SANtricity 软件中的厚卷和薄卷
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
厚卷始终是完全配置的，这意味着在创建卷时将分配所有容量。精简卷始终是精简配置的，这意味着在将数据写入卷时会分配容量。

[NOTE]
====
System Manager 不提供创建精简卷的选项。如果要创建精简卷，请使用命令行界面 (CLI)。

====
[cols="25h,~"]
|===
| 卷类型 | 说明 


 a| 
厚卷
 a| 
* 厚卷是从池或卷组创建的。
* 对于厚卷，会预先提供大量存储空间，以满足未来的存储需求。
* 密集卷是在创建卷时在物理存储上预分配卷的整个大小而创建的。这种预分配意味着创建 100 GiB 的卷实际上会消耗驱动器上 100 GiB 的已分配容量。但是，空间可能仍未使用，导致存储容量利用不足。
* 创建厚卷时，请确保不要过度分配单个卷的容量。过度分配单个卷的容量会迅速消耗系统中的所有物理存储。
* 请记住，拷贝服务（快照映像、快照卷、卷拷贝和异步镜像）也需要存储容量，因此不要将所有容量分配给厚卷。空间不足可能会阻止对池或卷组的写入。如果发生这种情况，您将收到空闲容量警报阈值警告。




 a| 
精简卷
 a| 
* 精简卷仅从池创建，而不是从卷组创建。
* 精简卷必须为 RAID 6。
* EF600/EF600C 或 EF300/EF300C 存储系统上没有可用的精简卷。
* 您必须使用 CLI 创建精简卷。
* 与厚卷不同，精简卷所需的空间不会在创建过程中分配，而是在以后按需提供。
* 精简卷可让您过度分配其大小。也就是说，您可以分配大于卷大小的 LUN 大小。然后，您可以根据需要扩展卷（如果需要，在此过程中添加驱动器），而无需扩展 LUN 的大小，因此无需断开用户连接。
* 您可以使用精简配置块空间回收 (UNMAP)，通过主机发出的 SCSI UNMAP 命令回收存储阵列上精简配置卷的块。支持精简配置的存储阵列可以重新调整回收空间的用途，以满足同一存储阵列中其他精简配置卷的分配请求，从而更好地报告磁盘空间消耗情况并更有效地利用资源。


|===


== 精简卷限制

精简卷支持与厚卷相同的所有操作，但以下情况除外：

* 您无法更改精简卷的段大小。
* 无法对精简卷启用预读冗余检查。
* 在 Copy Volume 操作中，不能使用精简卷作为目标卷。
* 只能在异步镜像对的主端更改精简卷的分配容量限制和警告阈值。主端对这些参数的任何更改都会自动传播到辅助端。
