= 更改 SANtricity System Manager 中池的配置设置
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
您可以编辑池的设置，包括其名称、容量警报设置、修改优先级和保留容量。

.关于此任务
此任务描述如何更改池的配置设置。

[NOTE]
====
无法使用 System Manager 界面更改池的 RAID 级别。System Manager 自动将池配置为 RAID 6。

====
.步骤
. 选择菜单：Storage[Pools & Volume Groups]。
. 选择要编辑的池，然后单击 *View/Edit Settings*。
+
此时将显示池设置对话框。

. 选择 *Settings* 选项卡，然后根据需要编辑池设置。
+
.字段详细信息
[%collapsible]
====
[cols="25h,~"]
|===
| 设置 | 说明 


 a| 
名称
 a| 
您可以更改用户提供的池名称。需要指定池的名称。



 a| 
容量警报
 a| 
您可以在池中的可用容量达到或超过指定阈值时发送警报通知。当存储在池中的数据超过指定阈值时，System Manager 将发送一条消息，允许您有时间添加更多存储空间或删除不必要的对象。

警报显示在仪表板的通知区域，可以通过电子邮件和 SNMP 陷阱消息从服务器发送给管理员。

您可以定义以下容量警报：

** *严重警报* -- 当池中的可用容量达到或超过指定阈值时，此严重警报会通知您。使用微调器控件调整阈值百分比。选中复选框以禁用此通知。
** *早期警报* -- 当池中的可用容量达到指定阈值时，此早期警报会通知您。使用微调器控件调整阈值百分比。选中复选框以禁用此通知。




 a| 
修改优先级
 a| 
您可以相对于系统性能指定池中修改操作的优先级。池中修改操作的优先级越高，操作完成速度越快，但会降低主机 I/O 性能。优先级较低会导致操作耗时较长，但主机 I/O 性能影响较小。

您可以选择五个优先级：最低、低、中、高和最高。优先级越高，对主机 I/O 和系统性能的影响就越大。

** *关键重建优先级* -- 当多个驱动器故障导致某些数据没有冗余且额外的驱动器故障可能导致数据丢失时，此滑块确定数据重建操作的优先级。
** *降级的重建优先级* -- 此滑动条确定驱动器发生故障时数据重建操作的优先级，但数据仍具有冗余，并且额外的驱动器故障不会导致数据丢失。
** *后台操作优先级* -- 此滑动条确定池处于最佳状态时发生的池后台操作的优先级。这些操作包括 Dynamic Volume Expansion (DVE)、Instant Availability Format (IAF) 以及将数据迁移到更换或添加的驱动器。




 a| 
保存容量（EF600 或 EF300 的"优化容量"）
 a| 
*保留容量* -- 您可以定义驱动器数量，以确定池上保留的容量，以支持潜在的驱动器故障。当发生驱动器故障时，保留容量用于保存重建的数据。池在数据重建过程中使用保留容量，而不是在卷组中使用的热备用驱动器。

使用微调器控制来调整驱动器数量。根据驱动器数量，池中的保留容量显示在微调器框旁边。

请记住以下有关保存容量的信息。

** 由于从池的总可用容量中减去保留容量，因此保留的容量会影响可用于创建卷的可用容量。如果为保留容量指定 0，则池中的所有可用容量将用于创建卷。
** 如果减少保存容量，则会增加可用于池卷的容量。


*额外的优化容量*（仅限 EF600 和 EF300 阵列）-- 创建池时，将生成推荐的优化容量，以提供可用容量与性能和驱动器磨损寿命之间的平衡。您可以通过向右移动滑块来调整此平衡，以获得更好的性能和驱动器磨损寿命，但会减少可用容量，或者向左移动滑块以增加可用容量，但会降低性能和驱动器磨损寿命。

当未分配部分容量时，SSD 驱动器将具有更长的使用寿命和更好的最大写入性能。对于与池相关联的驱动器，未分配的容量包括池的保留容量、可用容量（卷未使用的容量）以及作为额外优化容量预留的可用容量的一部分。额外的优化容量通过减少可用容量来确保最低限度的优化容量，因此无法用于卷创建。

|===
====
. 单击 *Save*。
