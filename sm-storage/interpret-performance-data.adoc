= 在 SANtricity System Manager 中解释性能数据
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
性能数据可以指导您调整存储阵列的性能。

在解读性能数据时，请记住，有几个因素会影响存储阵列的性能。下表介绍了需要考虑的主要方面。

[cols="25h,~"]
|===
| 性能数据 | 对性能调整的影响 


 a| 
延迟（毫秒或 ms）
 a| 
监控特定对象的 I/O 活动。

识别可能存在瓶颈的对象：

* 如果一个卷组在多个卷之间共享，则各个卷可能需要自己的卷组来提高驱动器的顺序性能并降低延迟。
* 使用池时，会引入更大的延迟，并且驱动器之间可能存在不均匀的工作负载，从而使延迟值变得不那么有意义，并且通常会更高。
* 驱动器类型和速度会影响延迟。使用随机 I/O，更快的旋转驱动器花费更少的时间在磁盘上的不同位置之间移动。
* 驱动器太少会导致更多的命令排队，并使驱动器处理命令的时间更长，从而增加了系统的一般延迟。
* 较大的 I/O 由于传输数据涉及额外时间而具有更大的延迟。
* 较高的延迟可能表明 I/O 模式本质上是随机的。具有随机 I/O 的驱动器将比具有顺序流的驱动器具有更大的延迟。
* 常见卷组的驱动器或卷之间的延迟差异可能表明驱动器速度较慢。




 a| 
IOPS
 a| 
影响每秒输入/输出操作（IOPS 或 IOs/sec）的因素包括以下内容：

* 访问模式（随机或顺序）
* I/O 大小
* RAID 级别
* 缓存块大小
* 是否启用读缓存
* 是否启用写缓存
* 动态缓存读取预取
* 区块大小
* 卷组或存储阵列中的驱动器数


缓存命中率越高，I/O 速率就越高。与禁用相比，启用写缓存会遇到更高的写入 I/O 速率。在决定是否为单个卷启用写缓存时，请查看当前 IOPS 和最大 IOPS。与随机 I/O 模式相比，顺序 I/O 模式的速率应该更高。无论您的 I/O 模式如何，都要启用写缓存，以最大限度地提高 I/O 速率并缩短应用程序响应时间。

您可以在卷的 IOPS 统计信息中查看更改段大小所带来的性能改进。尝试确定最佳段大小，或使用文件系统大小或数据库块大小。



 a| 
MiB/秒
 a| 
传输或吞吐率由应用程序 I/O 大小和 I/O 速率决定。通常，较小的应用程序 I/O 请求会导致较低的传输速率，但会提供更快的 I/O 速率和更短的响应时间。使用更大的应用程序 I/O 请求，可以实现更高的吞吐率。

了解典型的应用程序 I/O 模式可以帮助您确定特定存储阵列的最大 I/O 传输速率。



 a| 
CPU
 a| 
该值是正在使用的处理容量的百分比。

您可能会注意到相同类型对象的 CPU 使用率存在差异。例如，一个控制器的 CPU 使用率较高或随着时间的推移而增加，而另一个控制器的 CPU 使用率较轻或更稳定。在这种情况下，您可能需要将一个或多个卷的控制器所有权更改为 CPU 百分比较低的控制器。

您可能需要监控整个存储阵列的 CPU。如果随着时间的推移 CPU 继续增加，而应用程序性能降低，则可能需要添加存储阵列。通过将存储阵列添加到企业，您可以继续以可接受的性能级别满足应用程序需求。



 a| 
性能余量
 a| 
净空是指控制器、控制器主机通道和控制器驱动器通道的剩余性能能力。此值以百分比表示，表示这些对象能够提供的最大可能性能与当前性能水平之间的差距。

* 对于控制器，余量是最大可能 IOPS 的百分比。
* 对于通道，净空是最大吞吐量的百分比，即 MiB/s。计算中包括读吞吐量、写吞吐量和双向吞吐量。


|===
