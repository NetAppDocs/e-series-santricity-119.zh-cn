= 了解 SANtricity 软件中的卷术语
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
了解卷术语如何适用于您的存储阵列。



[[all-volume-types]]
== 所有卷类型

[cols="25h,~"]
|===
| 术语 | 说明 


 a| 
已分配容量
 a| 
您可以使用分配的容量来创建卷和进行复制服务操作。

对于厚卷，分配的容量和报告的容量是相同的，但对于精简卷，分配的容量和报告的容量是不同的。对于厚卷，物理分配的空间等于向主机报告的空间。对于精简卷，报告的容量是报告给主机的容量，而分配的容量是当前分配用于写入数据的驱动器空间量。



 a| 
应用程序
 a| 
应用程序是 SQL Server 或 Exchange 等软件。您可以定义一个或多个工作负载来支持每个应用程序。对于某些应用程序，系统会自动推荐优化存储的卷配置。卷配置中包括 I/O 类型、段大小、控制器所有权以及读写缓存等特征。



 a| 
容量
 a| 
容量是可以存储在卷中的数据量。



 a| 
控制器所有权
 a| 
控制器所有权定义了被指定为卷的所有者或主控制器的控制器。卷可以具有"`拥有`"卷的首选控制器（A 或 B）。使用 Automatic Load Balancing 功能自动调整卷所有权，以便在工作负载跨控制器转移时纠正任何负载平衡问题。Automatic Load Balancing 提供自动 I/O 工作负载平衡，并确保来自主机的传入 I/O 流量在两个控制器之间进行动态管理和平衡。



 a| 
动态缓存读取预取
 a| 
动态缓存读取预取允许控制器在将数据块从驱动器读取到缓存时将额外的顺序数据块复制到缓存中。这种缓存增加了将来从缓存中填充数据请求的可能性。动态缓存读取预取对于使用顺序 I/O 的多媒体应用程序非常重要。预取到缓存的数据速率和数量是根据主机读取的速率和请求大小自行调整的。随机访问不会导致数据被预取到缓存中。禁用读缓存时，此功能不适用。

对于精简卷，动态缓存读取预取始终被禁用且无法更改。



 a| 
可用容量区域
 a| 
可用容量区域是删除卷或在卷创建过程中未使用所有可用容量而产生的可用容量。在具有一个或多个可用容量区域的卷组中创建卷时，卷的容量仅限于该卷组中最大的可用容量区域。例如，如果一个卷组总共有 15 GiB 的可用容量，并且最大的可用容量区域为 10 GiB，则可以创建的最大卷为 10 GiB。

通过整合可用容量，您可以从卷组中的最大可用容量创建其他卷。



 a| 
主机
 a| 
主机是向存储阵列上的卷发送 I/O 的服务器。



 a| 
主机集群
 a| 
主机集群是一组主机。您可以创建主机集群，以便轻松地将相同的卷分配给多个主机。



 a| 
热备用驱动器
 a| 
仅卷组支持热备盘驱动器。热备盘驱动器不包含任何数据，并在卷组中 RAID 1、RAID 3、RAID 5 或 RAID 6 卷中的驱动器出现故障时充当备用驱动器。热备盘驱动器为您的存储阵列增加了另一个级别的冗余。



 a| 
LUN
 a| 
逻辑单元号 (LUN) 是分配给主机用于访问卷的地址空间的编号。此卷以 LUN 的形式作为容量呈现给主机。

每个主机都有自己的 LUN 地址空间。因此，不同的主机可以使用相同的 LUN 来访问不同的卷。



 a| 
媒体扫描
 a| 
介质扫描提供了一种在从驱动器正常读取或写入驱动器期间发现驱动器介质错误之前检测驱动器介质错误的方法。介质扫描作为后台操作执行，并扫描定义的用户卷中的所有数据和冗余信息。



 a| 
命名空间
 a| 
命名空间是为块访问而格式化的 NVM 存储。它类似于 SCSI 中的逻辑单元，它与存储阵列中的卷相关。



 a| 
池
 a| 
池是逻辑上分组的一组驱动器。您可以使用池创建一个或多个可供主机访问的卷。（您可以从池或卷组创建卷。）



 a| 
池或卷组容量
 a| 
池、卷或卷组容量是指已分配给池或卷组的存储阵列中的容量。此容量用于创建卷并为复制服务操作和存储对象的各种容量需求提供服务。



 a| 
读取缓存
 a| 
读缓存是存储已从驱动器读取的数据的缓冲区。读取操作的数据可能已经存在于先前操作的缓存中，因此无需访问驱动器。数据保留在读缓存中，直到刷新为止。



 a| 
已报告容量
 a| 
报告容量是报告给主机并可由主机访问的容量。

对于厚卷，报告的容量和分配的容量是相同的，但对于精简卷则不同。对于厚卷，物理分配的空间等于向主机报告的空间。对于精简卷，报告的容量是报告给主机的容量，而分配的容量是当前分配用于写入数据的驱动器空间量。



 a| 
区块大小
 a| 
段是在存储阵列移动到条带中的下一个驱动器（RAID 组）之前存储在驱动器上的数据量，以千字节 (KiB) 为单位。段大小等于或小于卷组的容量。池的段大小是固定的，不能更改。



 a| 
条带化
 a| 
条带化是在存储阵列上存储数据的方式。条带化将数据流拆分为特定大小的块（称为"块大小"），然后将这些块逐个写入驱动器。这种数据存储方式用于在多个物理驱动器上分发和存储数据。条带化是 RAID 0 的同义词，它将数据分散到 RAID 组中的所有驱动器上而不进行奇偶校验。



 a| 
卷
 a| 
卷是应用程序、数据库和文件系统存储数据的容器。它是为主机创建的逻辑组件，用于访问存储阵列上的存储。



 a| 
卷分配
 a| 
卷分配是将主机 LUN 分配给一个卷的方式。



 a| 
卷名称
 a| 
卷名是创建卷时分配给卷的字符串。您可以接受默认名称，也可以提供一个更具描述性的名称来指示卷中存储的数据类型。



 a| 
卷组
 a| 
卷组是具有共享特征的卷的容器。卷组具有定义的容量和 RAID 级别。您可以使用卷组创建一个或多个可供主机访问的卷。（您可以从卷组或池创建卷。）



 a| 
工作负载
 a| 
工作负载是支持应用程序的存储对象。可以为每个应用程序定义一个或多个工作负载或实例。对于某些应用程序，系统将工作负载配置为包含具有类似底层卷特征的卷。这些卷特性是根据工作负载支持的应用程序类型进行优化的。例如，如果创建支持 Microsoft SQL Server 应用程序的工作负载，然后为该工作负载创建卷，则会优化基础卷特征以支持 Microsoft SQL Server。



 a| 
写入缓存
 a| 
写缓存是存储来自主机尚未写入驱动器的数据的缓冲区。数据将保留在写缓存中，直到写入驱动器。写缓存可以提高 I/O 性能。



 a| 
使用镜像写入缓存
 a| 
当写入一个控制器的缓存内存的数据也写入另一个控制器的缓存内存时，将发生镜像写入缓存。因此，如果一个控制器发生故障，另一个控制器可以完成所有未完成的写入操作。仅当写缓存已启用且存在两个控制器时，写缓存镜像才可用。使用镜像进行写缓存是创建卷时的默认设置。



 a| 
不使用电池的写入缓存
 a| 
没有电池的写缓存设置允许写缓存继续，即使电池丢失、故障、完全放电或未完全充电。通常不建议选择没有电池的写缓存，因为如果断电，数据可能会丢失。通常，控制器会暂时关闭写缓存，直到电池充电或更换故障电池。

|===


[[specific-to-thin-volumes]]
== 特定于精简卷

[NOTE]
====
System Manager 不提供创建精简卷的选项。如果要创建精简卷，请使用命令行界面 (CLI)。

====
[NOTE]
====
EF600/EF600C 或 EF300/EF300C 存储系统上没有可用的精简卷。

====
[cols="25h,~"]
|===
| 术语 | 说明 


 a| 
已分配容量限制
 a| 
分配容量限制是精简卷分配的物理容量可以增长的上限。



 a| 
写入容量
 a| 
写入容量是从为精简卷分配的预留容量中已写入的容量大小。



 a| 
警告阈值
 a| 
您可以设置警告阈值警报，以便在精简卷的分配容量达到已满百分比（警告阈值）时发出。

|===
