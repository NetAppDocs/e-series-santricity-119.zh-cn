= SANtricity System Manager 的池和卷组常见问题解答
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
如果您只是在寻找问题的快速答案，此常见问题可以为您提供帮助。



[[what-is-a-volume-group]]
== 什么是卷组？

卷组是具有共享特征的卷的容器。卷组具有定义的容量和 RAID 级别。您可以使用卷组创建一个或多个可供主机访问的卷。（您可以从卷组或池创建卷。）



[[what-is-a-pool]]
== 什么是池？

池是逻辑上分组的一组驱动器。您可以使用池创建一个或多个可供主机访问的卷。（您可以从池或卷组创建卷。）

池可以消除管理员监视每个主机上的使用情况以确定它们何时可能耗尽存储空间并避免传统磁盘大小调整中断的需要。当池接近耗尽时，可以无中断地将其他驱动器添加到池中，并且容量增长对主机是透明的。

使用池，数据会自动重新分配以保持平衡。通过在整个池中分配奇偶校验信息和备用容量，池中的每个驱动器都可用于重建出现故障的驱动器。这种方法不使用专用热备盘驱动器，而是在整个池中保留保存（备用）容量。驱动器出现故障时，读取其他驱动器上的段以重新创建数据。然后选择一个新的驱动器来写入故障驱动器上的每个段，以便保持驱动器之间的数据分布。



[[what-is-reserved-capacity]]
== 什么是预留容量？

保留容量是物理分配的容量，用于存储快照映像、一致性组成员卷和镜像对卷等复制服务对象的数据。

与复制服务操作关联的保留容量卷驻留在池或卷组中。您可以从池或卷组创建保留容量。



[[what-is-fdefips-security]]
== 什么是 FDE/FIPS 安全？

FDE/FIPS 安全是指在写入期间加密数据并在读取期间使用唯一加密密钥解密数据的具有安全功能的驱动器。这些具有安全功能的驱动器可防止对从存储阵列中物理移除的驱动器上的数据进行未经授权的访问。

支持安全的驱动器可以是全磁盘加密 (FDE) 驱动器或联邦信息处理标准 (FIPS) 驱动器。FIPS 驱动器已通过认证测试。

[NOTE]
====
对于需要 FIPS 支持的卷，仅使用 FIPS 驱动器。在卷组或池中混合 FIPS 和 FDE 驱动器将导致所有驱动器被视为 FDE 驱动器。此外，FDE 驱动器不能添加到全 FIPS 卷组或池中或用作备件。

====


[[what-is-redundancy-check]]
== 什么是冗余检查？

冗余检查确定池或卷组中的卷上的数据是否一致。冗余数据用于在池或卷组中的一个驱动器发生故障时快速重建替换驱动器上的信息。

一次只能对一个池或卷组执行此检查。卷冗余检查执行以下操作：

* 扫描 RAID 3 卷、RAID 5 卷或 RAID 6 卷中的数据块，然后检查每个块的冗余信息。（只能使用命令行界面将 RAID 3 分配给卷组。）
* 比较 RAID 1 镜像驱动器上的数据块。
* 如果控制器固件确定数据不一致，则返回冗余错误。


[NOTE]
====
立即对同一个池或卷组运行冗余检查可能会导致错误。要避免此问题，请等待一到两分钟，然后再对同一个池或卷组运行另一个冗余检查。

====


[[what-are-the-differences-between-pools-and-volume-groups]]
== 池和卷组之间有什么区别？

池类似于卷组，具有以下差异。

* 池中的数据随机存储在池中的所有驱动器上，而卷组中的数据存储在同一组驱动器上。
* 在驱动器发生故障时，池具有较少的性能降级，并且重建所需的时间较短。
* 池具有内置的保存容量，因此不需要专用的热备盘驱动器。
* 池允许对大量驱动器进行分组。
* 池不需要指定的 RAID 级别。




[[why-would-i-want-to-manually-configure-a-pool]]
== 为什么要手动配置池？

以下示例说明了为什么要手动配置池。

* 如果存储阵列上有多个应用程序，并且不希望它们竞争相同的驱动器资源，则可以考虑为一个或多个应用程序手动创建一个较小的池。
+
您可以只分配一个或两个卷，而不是将工作负载分配给具有多个卷的大型池来分发数据。手动创建一个专用于特定应用程序工作负载的单独池，可以使存储阵列操作执行得更快，争用更少。

+
要手动创建池：选择 *Storage*，然后选择 *Pools & Volume Groups*。在 All Capacity 选项卡中，单击菜单：Create[Pool]。

* 如果存在相同驱动器类型的多个池，则会显示一条消息，指示 System Manager 无法自动为池推荐驱动器。但是，您可以手动将驱动器添加到现有池中。
+
要手动将驱动器添加到现有池：从 Pools & Volume Groups 页面，选择池，然后单击 *Add Capacity*。





[[why-are-capacity-alerts-important]]
== 为什么容量警报很重要？

容量警报指示何时将驱动器添加到池中。池需要足够的可用容量才能成功执行存储阵列操作。您可以通过配置 SANtricity System Manager 在池的可用容量达到或超过指定百分比时发送警报来防止这些操作中断。

在使用 *Pool auto-configuration* 选项或 *Create pool* 选项创建池时，可以设置此百分比。如果您选择自动选项，默认设置会自动确定您何时收到提醒通知。如果选择手动创建池，则可以确定提醒通知设置；如果愿意，则可以接受默认设置。您可以稍后在 menu:Settings[Alerts] 中调整这些设置。

[NOTE]
====
当池中的可用容量达到指定的百分比时，将使用您在警报配置中指定的方法发送警报通知。

====


[[why-cant-i-increase-my-preservation-capacity]]
== 为什么我无法增加保存容量？

如果已在所有可用的可用容量上创建了卷，则可能无法增加保留容量。

保留容量是在池上保留以支持潜在驱动器故障的容量（驱动器数量）。创建池时，系统会根据池中的驱动器数量自动保留默认的保留容量。如果已为所有可用容量创建了卷，则如果不通过添加驱动器或删除卷向池中添加容量，则无法增加保留容量。

您可以从 *Pools & Volume Groups* 更改保留容量。选择要编辑的池。单击 *View/Edit Settings*，然后选择 *Settings* 选项卡。

[NOTE]
====
保留容量指定为驱动器数量，即使实际保留容量分布在池中的驱动器之间。

====


[[is-there-a-limit-on-the-number-of-drives-i-can-remove-from-a-pool]]
== 我可以从池中删除的驱动器数量是否有限制？

SANtricity System Manager 为可以从池中删除的驱动器数量设置限制。

* 您不能将池中的驱动器数量减少到少于 11 个驱动器。
* 如果在将数据重新分配给池中的剩余驱动器时，池中的可用容量不足以包含已删除驱动器中的数据，则无法删除驱动器。
* 一次最多可以删除 60 个驱动器。如果选择的驱动器超过 60 个，则"删除驱动器"选项将被禁用。如果需要删除超过 60 个驱动器，请重复"删除驱动器"操作。




[[what-media-types-are-supported-for-a-drive]]
== 驱动器支持哪些媒体类型？

支持以下媒体类型：硬盘驱动器 (HDD) 和固态硬盘 (SSD)。



[[why-are-some-drives-not-showing-up]]
== 为什么有些驱动器没有显示？

在添加容量对话框中，并非所有驱动器都可用于向现有池或卷组添加容量。

由于以下任何原因，驱动器不符合条件：

* 驱动器必须取消分配且未启用安全功能。已成为另一个池、另一个卷组一部分或配置为热备盘的驱动器不符合条件。如果驱动器未分配但已启用安全功能，您必须手动擦除该驱动器才能使其符合条件。
* 处于非最佳状态的驱动器不符合条件。
* 如果驱动器的容量太小，则不符合条件。
* 驱动器介质类型必须在池或卷组内匹配。您不能混合以下内容：
+
** 带固态硬盘 (SSD) 的硬盘驱动器 (HDD)
** 使用 SAS 驱动器的 NVMe
** 具有 512 字节和 4KiB 卷块大小的驱动器


* 如果池或卷组包含所有支持安全的驱动器，则不会列出不支持安全的驱动器。
* 如果池或卷组包含所有联邦信息处理标准 (FIPS) 驱动器，则不列出非 FIPS 驱动器。
* 如果池或卷组包含所有支持 Data Assurance (DA) 的驱动器，并且池或卷组中至少有一个启用 DA 的卷，则不支持 DA 的驱动器不符合条件，因此无法将其添加到该池或卷组。但是，如果池或卷组中没有启用 DA 的卷，则可以将不支持 DA 的驱动器添加到该池或卷组。如果您决定混合使用这些驱动器，请记住您无法创建任何启用 DA 的卷。


[NOTE]
====
可以通过添加新驱动器或删除池或卷组来增加存储阵列的容量。

====

[[what-is-the-optimal-drive-positioning-for-pools-and-volume-groups]]
== 池和卷组的最佳驱动器定位是什么？

创建池和卷组时，请确保在上驱动器插槽和下驱动器插槽之间平衡驱动器选择。

对于 EF600 和 EF300 控制器，驱动器插槽 0-11 连接到一个 PCI 网桥，而插槽 12-23 连接到不同的 PCI 网桥。为了获得最佳性能，您应该平衡驱动器选择，以包括来自上下插槽的大致相等数量的驱动器。这种定位可确保您的卷不会在必要时提前达到带宽限制。



[[what-raid-level-is-best-for-my-application]]
== 哪个 RAID 级别最适合我的应用程序？

要最大限度地提高卷组的性能，必须选择适当的 RAID 级别。您可以通过了解正在访问卷组的应用程序的读取和写入百分比来确定适当的 RAID 级别。使用"性能"页面获取这些百分比。



[[raid-levels-and-application-performance]]
=== RAID 级别和应用程序性能

RAID 依赖于一系列名为 _levels_ 的配置，以确定如何从驱动器写入和检索用户和冗余数据。每个 RAID 级别提供不同的性能功能。由于 RAID 5 和 RAID 6 配置的出色读取性能，具有高读取百分比的应用程序在使用 RAID 5 卷或 RAID 6 卷时将表现良好。

读取百分比较低（写入密集型）的应用程序在 RAID 5 卷或 RAID 6 卷上的性能不佳。性能下降是由于控制器将数据和冗余数据写入 RAID 5 卷组或 RAID 6 卷组中的驱动器的方式造成的。

根据以下信息选择 RAID 级别。

*RAID 0*

* *说明*
+
** 非冗余、条带化模式。


* *工作原理*
+
** RAID 0 在卷组中的所有驱动器上对数据进行条带化。


* *数据保护功能*
+
** 对于高可用性需求，不建议使用 RAID 0。RAID 0 更适合非关键数据。
** 如果卷组中的单个驱动器出现故障，则所有关联的卷都会出现故障，并且所有数据都会丢失。


* *驱动器数量要求*
+
** RAID 级别 0 至少需要一个驱动器。
** RAID 0 卷组可以有 30 个以上的驱动器。
** 您可以创建一个包含存储阵列中所有驱动器的卷组。




*RAID 1 或 RAID 10*

* *说明*
+
** 条带化/镜像模式。


* *工作原理*
+
** RAID 1 使用磁盘镜像将数据同时写入两个重复磁盘。
** RAID 10 使用驱动器条带化对一组镜像驱动器对中的数据进行条带化。


* *数据保护功能*
+
** RAID 1 和 RAID 10 提供高性能和最佳数据可用性。
** RAID 1 和 RAID 10 使用驱动器镜像从一个驱动器精确拷贝到另一个驱动器。
** 如果驱动器对中的一个驱动器发生故障，存储阵列可以立即切换到另一个驱动器，而不会丢失任何数据或服务。
** 单个驱动器故障会导致相关卷降级。镜像驱动器允许访问数据。
** 卷组中的驱动器对故障会导致所有关联的卷发生故障，并可能发生数据丢失。


* *驱动器数量要求*
+
** RAID 1 至少需要两个驱动器：一个驱动器用于用户数据，一个驱动器用于镜像数据。
** 如果选择四个或更多驱动器，则会在整个卷组中自动配置 RAID 10：两个驱动器用于用户数据，两个驱动器用于镜像数据。
** 卷组中必须有偶数个驱动器。如果您没有偶数个驱动器，并且还有一些未分配的驱动器，请转到 *Pools & Volume Groups* 以向卷组添加其他驱动器，然后重试该操作。
** RAID 1 和 RAID 10 卷组可以有 30 个以上的驱动器。可以创建一个包含存储阵列中所有驱动器的卷组。




*RAID 5*

* *说明*
+
** 高 I/O 模式。


* *工作原理*
+
** 用户数据和冗余信息（奇偶校验）在驱动器上进行条带化。
** 一个驱动器的等效容量用于冗余信息。


* *数据保护功能*
+
** 如果 RAID 5 卷组中的单个驱动器发生故障，则所有关联的卷都将降级。冗余信息仍然允许访问数据。
** 如果 RAID 5 卷组中有两个或多个驱动器发生故障，则所有关联的卷都会出现故障，并且所有数据都会丢失。


* *驱动器数量要求*
+
** 卷组中必须至少有三个驱动器。
** 通常，卷组中最多只能有 30 个驱动器。




*RAID 6*

* *说明*
+
** 高 I/O 模式。


* *工作原理*
+
** 用户数据和冗余信息（双奇偶校验）在驱动器上进行条带化。
** 两个驱动器的等效容量用于冗余信息。


* *数据保护功能*
+
** 如果 RAID 6 卷组中有一个或两个驱动器发生故障，则所有关联的卷都会降级，但冗余信息仍允许访问数据。
** 如果 RAID 6 卷组中有三个或更多驱动器发生故障，则所有关联的卷都会出现故障，并且所有数据都会丢失。


* *驱动器数量要求*
+
** 卷组中必须至少有五个驱动器。
** 通常，卷组中最多只能有 30 个驱动器。




[NOTE]
====
不能更改池的 RAID 级别。用户界面自动将池配置为 RAID 6。

====


[[raid-levels-and-data-protection]]
=== RAID 级别和数据保护

RAID 1、RAID 5 和 RAID 6 将冗余数据写入驱动器介质以实现容错。冗余数据可以是数据的副本（镜像）或从数据导出的纠错代码。如果驱动器发生故障，您可以使用冗余数据快速重建替换驱动器上的信息。

您可以在单个卷组中配置单个 RAID 级别。该卷组的所有冗余数据都存储在卷组内。卷组的容量是成员驱动器的总容量减去为冗余数据保留的容量。冗余所需的容量取决于所使用的 RAID 级别。



[[what-is-data-assurance]]
== 什么是数据保障？

数据保障 (DA) 实施 T10 Protection Information (PI) 标准，该标准通过检查和纠正沿 I/O 路径传输数据时可能发生的错误来提高数据完整性。

Data Assurance 功能的典型使用将检查控制器和驱动器之间的 I/O 路径部分。DA 功能在池和卷组级别呈现。

启用此功能后，存储阵列会将错误检查代码（也称为循环冗余检查或 CRC）附加到卷中的每个数据块。移动数据块后，存储阵列使用这些 CRC 代码来确定在传输过程中是否发生任何错误。潜在损坏的数据既不会写入磁盘，也不会返回到主机。如果要使用 DA 功能，请在创建新卷时选择支持 DA 的池或卷组（在池和卷组候选表中的"DA"旁边查找"是"）。

确保使用支持 DA 的 I/O 接口将这些启用 DA 的卷分配给主机。支持 DA 的 I/O 接口包括光纤通道、SAS、TCP/IP 上的 iSCSI、NVMe/FC、NVMe/IB、NVME/RoCE 和 iSER over InfiniBand（用于 RDMA/IB 的 iSCSI 扩展）。SRP over InfiniBand 不支持 DA。



[[what-is-secure-capable-drive-security]]
== 什么是安全功能 (Drive Security)？

驱动器安全是一项功能，可防止在从存储阵列中移除启用安全功能的驱动器时对其上的数据进行未经授权的访问。这些驱动器可以是全磁盘加密 (FDE) 驱动器或联邦信息处理标准 (FIPS) 驱动器。



[[what-do-i-need-to-know-about-increasing-reserved-capacity]]
== 关于增加预留容量，我需要知道什么？

通常，当您收到预留容量可能已满的警告时，您应该增加容量。您只能以 8 GiB 的增量增加预留容量。

* 您必须在池或卷组中具有足够的可用容量，以便在必要时可以对其进行扩展。
+
如果任何池或卷组上不存在可用容量，则可以将未分配的容量以未使用的驱动器的形式添加到池或卷组中。

* 池或卷组中的卷必须具有"最佳"状态，并且不得处于任何修改状态。
* 要用于增加容量的池或卷组中必须存在可用容量。
* 您不能增加只读快照卷的保留容量。只有读写快照卷需要保留容量。


对于快照操作，保留容量通常为基本卷的 40%。对于异步镜像操作，保留容量通常为基本卷的 20%。如果您认为基本卷将发生许多变化，或者存储对象的复制服务操作的估计预期寿命将非常长，请使用更高的百分比。



[[why-cant-i-choose-another-amount-to-decrease-by]]
== 为什么我不能选择其他减少金额？

您只能按照之前增加预留容量的数量来减少预留容量。成员卷的预留容量只能按照添加时的相反顺序进行删除。

如果存在以下条件之一，则无法降低存储对象的保留容量：

* 如果存储对象是镜像对卷。
* 如果存储对象仅包含一个用于保留容量的卷。存储对象必须至少包含两个用于保留容量的卷。
* 如果存储对象是禁用的快照卷。
* 如果存储对象包含一个或多个关联的快照映像。


您只能按照与添加时相反的顺序删除保留容量的卷。

无法减少只读快照卷的保留容量，因为它没有任何关联的保留容量。仅读写快照卷需要保留容量。



[[why-do-i-need-reserved-capacity-for-each-member-volume]]
== 为什么我需要为每个成员卷保留容量？

快照一致性组中的每个成员卷必须具有自己的保留容量，以保存主机应用程序对基本卷所做的任何修改，而不会影响引用的一致性组快照映像。保留容量为主机应用程序提供对指定为读写的成员卷中包含的数据副本的写入访问权限。

主机无法直接读取或写入一致性组快照映像。相反，快照映像仅用于保存从基础卷捕获的数据。

在创建指定为读写的一致性组快照卷期间，System Manager 为一致性组中的每个成员卷创建保留容量。此保留容量为主机应用程序提供了对一致性组快照映像中包含的数据副本的写入权限。



[[how-do-i-view-and-interpret-all-ssd-cache-statistics]]
== 如何查看和解释所有 SSD Cache 统计信息？

您可以查看 SSD Cache 的名义统计数据和详细统计数据。名义统计数据是详细统计数据的子集。

只有将所有 SSD 统计信息导出到  `.csv` 文件时，才能查看详细统计信息。在查看和解释统计数据时，请记住，一些解释是通过查看统计数据的组合得出的。



[[nominal-statistics]]
=== 名义统计

要查看 SSD Cache 统计信息，请选择菜单：Storage[Pools & Volume Groups]。选择要查看其统计信息的 SSD Cache，然后选择菜单：More[View Statistics]。标称统计信息显示在"View SSD Cache Statistics"对话框中。

以下列表包括名义统计数据，这些统计数据是详细统计数据的子集。

[cols="25h,~"]
|===
| 标称统计量 | 说明 


 a| 
读取/写入
 a| 
从启用 SSD Cache 的卷读取或向其写入的主机读取和主机写入总数。比较读取相对于写入的情况。读取需要大于写入才能有效执行 SSD Cache 操作。读取与写入的比例越大，缓存的操作就越好。



 a| 
缓存命中数
 a| 
缓存命中次数的计数。



 a| 
缓存命中率 (%)
 a| 
派生自 Cache Hits / (读取 + 写入)。要进行有效的 SSD Cache 操作，Cache Hit 百分比应大于 50%。一个小数字可以表示几件事：

* 读取与写入比率太小
* 不重复读取
* 缓存容量太小




 a| 
缓存分配 (%)
 a| 
分配的 SSD Cache 存储量，以此控制器可用的 SSD Cache 存储的百分比表示。从分配的字节/可用字节派生。Cache Allocation 百分比通常显示为 100%。如果此数字小于 100%，则表示缓存尚未预热，或者 SSD Cache 容量大于所有正在访问的数据。在后一种情况下，较小的 SSD Cache 容量可以提供相同的性能水平。请注意，这并不表示缓存数据已放入 SSD Cache；这只是将数据放入 SSD Cache 之前的一个准备步骤。



 a| 
缓存利用率 (%)
 a| 
包含来自启用卷的数据的 SSD Cache 存储量，以分配的 SSD Cache 存储的百分比表示。此值表示从用户数据字节/分配字节派生的 SSD Cache 的利用率或密度。Cache Utilization 百分比通常低于 100%，可能要低得多。此数字显示 SSD Cache 容量中充满缓存数据的百分比。此数字低于 100% 是因为 SSD Cache 的每个分配单元（SSD Cache 块）被划分为称为子块的较小单元，这些子块在某种程度上是独立填充的。数字越高通常越好，但即使数字较小，性能提升也可能很显著。

|===


[[detailed-statistics]]
=== 详细统计信息

详细统计数据由名义统计数据加上其他统计数据组成。这些其他统计数据与名义统计数据一起保存，但与名义统计数据不同，它们不会显示在"查看 SSD 缓存统计数据"对话框中。您只能在将统计信息导出到  `.csv` 文件后才能查看详细统计信息。

查看 `.csv` 文件时，请注意，详细统计信息列在标称统计信息之后：

[cols="25h,~"]
|===
| 详细统计信息 | 说明 


 a| 
读取块
 a| 
主机读取中的块数。



 a| 
写入块
 a| 
主机写入中的块数。



 a| 
完全命中块
 a| 
缓存命中中的块数。完全命中块表示已完全从 SSD Cache 读取的块数。SSD Cache 仅对完全缓存命中的操作有益于性能。



 a| 
部分命中
 a| 
SSD Cache 中至少有一个块（但不是所有块）的主机读取数。部分命中是 SSD Cache *未命中*，其中读取从基本卷得到满足。



 a| 
部分命中 - 块
 a| 
Partial Hits 中的块数。部分缓存命中和部分缓存命中块源于 SSD Cache 中只有部分数据的操作。在这种情况下，操作必须从缓存硬盘驱动器 (HDD) 卷获取数据。SSD Cache 对这种类型的命中不提供性能优势。如果部分缓存命中块计数高于完全缓存命中块，则不同的 I/O 特征类型（文件系统、数据库或 Web 服务器）可以提高性能。与 Cache Hits 相比，当 SSD Cache 预热时，预计会有更多的 Partial Hits 和 Misses。



 a| 
未命中
 a| 
SSD Cache 中没有任何块的主机读取数。当从基本卷满足读取时，会出现 SSD Cache 未命中。预计在 SSD Cache 预热时，部分命中和未命中的数量会比 Cache 命中更多。



 a| 
未命中 - 块
 a| 
Misses 中的块数。



 a| 
填充操作（主机读取）
 a| 
将数据从基本卷复制到 SSD Cache 的主机读取次数。



 a| 
填充操作（主机读取）- 块
 a| 
填充操作（主机读取）中的块数。



 a| 
填充操作（主机写入）
 a| 
将数据从基本卷复制到 SSD Cache 的主机写入次数。对于因写入 I/O 操作而未填充缓存的缓存配置设置，填充操作（主机写入）计数可能为零。



 a| 
填充操作（主机写入） - 块
 a| 
填充操作（主机写入）中的块数。



 a| 
使操作无效
 a| 
数据被无效或从 SSD Cache 中删除的次数。对于每个主机写入请求、具有强制单元访问 (FUA) 的每个主机读取请求、每个验证请求以及某些其他情况，都会执行缓存失效操作。



 a| 
回收操作
 a| 
SSD Cache 块已重复用于另一个基本卷和/或不同逻辑块寻址 (LBA) 范围的次数。为了有效的缓存操作，与读取和写入操作的组合数量相比，回收次数必须较少。如果回收操作数接近读取和写入总数，则 SSD Cache 发生颠簸。缓存容量需要增加或工作负载不适合与 SSD Cache 一起使用。



 a| 
可用字节
 a| 
SSD Cache 中可供此控制器使用的字节数。



 a| 
已分配字节
 a| 
此控制器从 SSD 缓存分配的字节数。从 SSD 缓存分配的字节可能为空，或者它们可能包含来自基本卷的数据。



 a| 
用户数据字节
 a| 
SSD 缓存中包含来自基本卷的数据的已分配字节数。可用字节、已分配字节和用户数据字节用于计算缓存分配百分比和缓存利用率百分比。

[[what-is-optimization-capacity-for-pools]]
== 什么是池的优化容量？

当未分配部分容量时，SSD 驱动器将具有更长的使用寿命和更好的最大写入性能。

对于与池相关联的驱动器，未分配的容量包括池的保留容量、可用容量（卷未使用的容量）和作为额外优化容量预留的可用容量的一部分。额外的优化容量通过减少可用容量来确保最低限度的优化容量，因此无法用于卷创建。

创建池时，将生成推荐的优化容量，以提供性能、驱动器磨损寿命和可用容量的平衡。位于池设置对话框中的其他优化容量滑块允许调整池的优化容量。调整滑块以牺牲可用容量为代价，提供更好的性能和驱动器磨损寿命，或以牺牲性能和驱动器磨损寿命为代价，提供额外的可用容量。

[NOTE]
====
附加优化容量滑块仅适用于 EF600 和 EF300 存储系统。

====


[[what-is-optimization-capacity-for-volume-groups]]
== 什么是卷组的优化容量？

当未分配部分容量时，SSD 驱动器将具有更长的使用寿命和更好的最大写入性能。

对于与卷组关联的驱动器，未分配容量由卷组的可用容量（卷未使用的容量）和可用容量的一部分作为优化容量组成。额外的优化容量通过减少可用容量来确保最低限度的优化容量，因此无法用于卷创建。

创建卷组时，将生成推荐的优化容量，以提供性能、驱动器磨损寿命和可用容量的平衡。卷组设置对话框中的附加优化容量滑块允许调整卷组的优化容量。调整滑块以牺牲可用容量为代价来提供更好的性能和驱动器磨损寿命，或以牺牲性能和驱动器磨损寿命为代价来增加可用容量。

[NOTE]
====
附加优化容量滑块仅适用于 EF600 和 EF300 存储系统。

====


[[what-is-resource-provisioning-capable]]
== 资源配置功能是什么？

资源调配是 EF300 和 EF600 存储阵列中提供的一项功能，它允许卷立即投入使用，而无需后台初始化过程。

资源调配的卷是 SSD 卷组或池中的厚卷，其中在创建卷时分配（分配给卷）驱动器容量，但取消分配（未映射）驱动器块。相比之下，在传统的厚卷中，所有驱动器块在后台卷初始化操作期间进行映射或分配，以初始化 Data Assurance 保护信息字段，并使每个 RAID 条带中的数据和 RAID 奇偶校验一致。使用资源调配的卷，没有时间限制的后台初始化。相反，每个 RAID 条带在第一次写入条带中的卷块时进行初始化。

资源调配的卷仅在 SSD 卷组和池上受支持，其中组或池中的所有驱动器都支持 NVMe Deallocated 或 Unwritten Logical Block Error Enable (DULBE) 错误恢复功能。创建资源调配的卷时，分配给该卷的所有驱动器块都将被取消分配（未映射）。此外，主机可以使用 NVMe Dataset Management 命令或 SCSI Unmap 命令取消分配卷中的逻辑块。取消分配块可以提高 SSD 磨损寿命并提高最大写入性能。每种驱动器型号和容量的改进程度各不相同。


NOTE: 目前 EF300C 或 EF600C 存储阵列不支持 DULBE。
