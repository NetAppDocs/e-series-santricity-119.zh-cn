= SANtricity System Manager 中警报的工作原理
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
警报通知管理员存储阵列上发生的重要事件。警报可以通过电子邮件、SNMP 陷阱和 syslog 发送。

警报流程的工作原理如下：

. 管理员在 System Manager 中配置以下一种或多种警报方法：
+
** *电子邮件* -- 消息将发送到电子邮件地址。
** *SNMP* -- SNMP 陷阱被发送到 SNMP 服务器。
** *Syslog* -- 消息发送到 syslog 服务器。


. 当存储阵列的事件监视器检测到问题时，它会将有关该问题的信息写入事件日志（可从菜单：Support[Event Log] 获取）。例如，问题可能包括电池故障、组件从 Optimal 移动到 Offline 或控制器中的冗余错误等事件。
. 如果事件监视器确定该事件是"可警报的"，则使用配置的警报方法（电子邮件、SNMP 和/或 syslog）发送通知。所有关键事件以及一些警告和信息事件都被认为是"可警报的"。




== 警报配置

您可以从初始设置向导（仅适用于电子邮件警报）或从警报页面配置警报。要检查当前配置，请转到菜单：Settings[Alerts]。

警报图块显示警报配置，可为以下选项之一：

* 未配置。
* 已配置；至少设置了一个警报方法。要确定配置了哪些警报方法，请将光标指向图块。




== 警报信息

警报可能包括以下类型的信息：

* 存储阵列的名称。
* 与事件日志条目相关的事件错误类型。
* 事件发生的日期和时间。
* 事件的简要描述。


[NOTE]
====
系统日志警报遵循 RFC 5424 消息传递标准。

====
