= 了解 SANtricity 镜像
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
SANtricity Unified Manager 包括 SANtricity 镜像功能的配置选项，使管理员能够在两个存储阵列之间复制数据以进行数据保护。

[NOTE]
====
EF600/EF600C 或 EF300/EF300C 存储系统上不提供同步镜像。

====


[[types-of-mirroring]]
== 镜像类型

SANtricity 应用程序包括两种类型的镜像 -- 异步和同步。

异步镜像可按需或按计划复制数据卷，从而最大限度地减少或避免可能因数据损坏或丢失而导致的停机时间。异步镜像捕获特定时间点的主卷的状态，并仅复制自上次图像捕获以来发生变化的数据。主站点可以立即更新，辅助站点可以在带宽允许的情况下更新。当网络资源可用时，信息将被缓存并稍后发送。这种类型的镜像非常适合备份和存档等定期流程。

同步镜像实时复制数据卷，以确保连续可用性。其目的是在两个存储阵列之一发生灾难时，通过提供重要数据的副本，实现零丢失数据的恢复点目标 (RPO)。副本在任何时刻都与生产数据相同，因为每次对主卷执行写入操作时，都会对辅助卷执行写入操作。在使用在主卷上所做的更改更新辅助卷之前，主机不会收到写入成功确认。这种类型的镜像非常适合用于业务连续性目的，例如灾难恢复。



[[differences-between-mirroring-types]]
== 镜像类型之间的差异

下表介绍了两种镜像类型之间的主要区别。

[cols="1a,1a,1a"]
|===
| 属性 | 异步 | 同步 


 a| 
复制方法
 a| 
时间点 -- 镜像按需完成或根据用户定义的计划自动完成。
 a| 
连续 -- 镜像会自动连续执行，从每次主机写入中复制数据。



 a| 
距离
 a| 
支持阵列之间的长距离。通常，距离仅受网络功能和通道扩展技术的限制。
 a| 
仅限于阵列之间的较短距离。通常，距离必须在本地存储阵列约 10 km（6.2 英里）范围内，以满足延迟和应用程序性能要求。



 a| 
通信方法
 a| 
标准 IP 或光纤通道网络。
 a| 
仅光纤通道网络。



 a| 
卷类型
 a| 
标准或精简。
 a| 
仅限标准。

|===
