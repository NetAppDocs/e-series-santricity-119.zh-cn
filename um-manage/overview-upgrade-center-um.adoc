= 了解 SANtricity Unified Manager 中的升级中心
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
从升级中心，您可以管理多个存储阵列的 SANtricity 操作系统软件和 NVSRAM 升级。



[[how-do-upgrades-work]]
== 升级如何运作？

下载最新的 OS 软件，然后升级一个或多个阵列。



[[upgrade-workflow]]
=== 升级工作流

以下步骤提供了执行软件升级的高级工作流。

. 您可以从支持站点下载最新的 SANtricity 操作系统软件文件（可在支持页面的 Unified Manager 中获得链接）。在管理主机系统（在浏览器中访问 Unified Manager 的主机）上保存文件，然后解压缩文件。
. 在 Unified Manager 中，您可以将 SANtricity 操作系统软件文件和 NVSRAM 文件加载到存储库（Web Services Proxy 服务器中存储文件的区域）。您可以从菜单中添加文件：升级中心[升级 SANtricity 操作系统软件或从升级中心 > 管理软件存储库]。
. 将文件加载到存储库中后，您可以选择要在升级中使用的文件。从升级 SANtricity 操作系统软件页面（菜单：升级中心[升级 SANtricity 操作系统软件]），选择 SANtricity 操作系统软件文件和 NVSRAM 文件。选择软件文件后，此页面上将显示兼容存储阵列的列表。然后选择要使用新软件升级的存储阵列。（不能选择不兼容的阵列。）
. 然后，您可以立即开始软件传输和激活，也可以选择稍后暂存文件以供激活。在升级过程中，Unified Manager 会执行以下任务：
+
.. 对存储阵列执行运行状况检查，以确定是否存在任何可能阻止升级完成的条件。如果任何阵列未通过运行状况检查，您可以跳过该特定阵列并继续升级其他阵列，也可以停止整个过程并对未通过的阵列进行故障排除。
.. 将升级文件传输到每个控制器。
.. 重新启动控制器并激活新的 SANtricity 操作系统软件，一次一个控制器。激活期间，现有的 SANtricity 操作系统文件将替换为新文件。
+
[NOTE]
====
您还可以指定稍后激活软件。

====






[[immediate-or-staged-upgrade]]
=== 立即或分阶段升级

您可以立即激活升级，也可以将其暂存以供稍后使用。出于以下原因，您可以选择稍后激活：

* *时间* -- 激活软件可能需要很长时间，因此您可能需要等待 I/O 负载较轻。根据 I/O 负载和缓存大小，控制器升级通常需要 15 到 25 分钟才能完成。在激活期间，控制器会重新启动并进行故障转移，因此在升级完成之前，性能可能会低于正常水平。
* *包类型* -- 在升级其他存储阵列上的文件之前，您可能需要在一个存储阵列上测试新软件和固件。


要激活暂存软件，请转到菜单：Support[Upgrade Center]，然后在标记为 SANtricity 操作系统控制器软件升级的区域中单击 *Activate*。



[[health-check]]
=== 运行状况检查

运行状况检查是升级过程的一部分，但您也可以在开始之前单独运行运行状况检查（转到菜单：Upgrade Center[Pre-Upgrade Health Check]）。

运行状况检查会评估所有存储系统组件，以确保可以继续升级。以下情况可能会阻止升级：

* 分配的驱动器出现故障
* 正在使用的热备件
* 不完整的卷组
* 正在运行独占操作
* 缺失卷
* 处于非最佳状态的控制器
* 事件日志事件数过多
* 配置数据库验证失败
* 带有旧版本 DACstore 的驱动器




[[what-do-i-need-to-know-before-upgrading]]
== 升级前需要了解哪些信息？

在升级多个存储阵列之前，请在规划过程中查看主要注意事项。



[[current-versions]]
=== 当前版本

您可以从 Unified Manager 的"管理"页面查看每个发现的存储阵列的当前 SANtricity 操作系统软件版本。版本显示在 SANtricity 操作系统软件列中。当您单击每行中的 SANtricity 操作系统版本时，控制器固件和 NVSRAM 信息在弹出对话框中可用。



[[other-components-requiring-upgrade]]
=== 需要升级的其他组件

作为升级过程的一部分，您可能还需要升级主机的多路径/故障转移驱动程序或 HBA 驱动程序，以便主机可以与控制器正确交互。

有关兼容性信息，请参见 https://imt.netapp.com/matrix/#welcome["NetApp 互操作性矩阵"^]。此外，请参见适用于您的操作系统的 Express Guides 中的步骤。Express Guides 可从 https://docs.netapp.com/us-en/e-series/index.html["E 系列和 SANtricity 文档"^]获得。



[[dual-controllers]]
=== 双控制器

如果存储阵列包含两个控制器，并且您安装了多路径驱动程序，则在升级过程中，存储阵列可以继续处理 I/O。在升级过程中，会发生以下过程：

. 控制器 A 将其所有 LUN 故障切换到控制器 B。
. 升级发生在控制器 A 上。
. 控制器 A 收回其 LUN 和控制器 B 的所有 LUN。
. 升级发生在控制器 B 上。


升级完成后，可能需要在控制器之间手动重新分配卷，以确保卷返回到正确的所有控制器。
