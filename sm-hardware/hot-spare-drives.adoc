= 了解 SANtricity System Manager 中的热备用驱动器
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
热备盘在 SANtricity System Manager 中充当 RAID 1、RAID 5 或 RAID 6 卷组的备用驱动器。

它们是功能齐全的驱动器，不包含任何数据。如果卷组中的驱动器出现故障，控制器会自动将故障驱动器的数据重建到分配为热备盘的驱动器。

热备盘不专用于特定的卷组。它们可用于存储阵列中的任何故障驱动器，只要热备盘和驱动器共享以下属性：

* 相等的容量（或热备盘的更大容量）
* 相同的介质类型（例如 HDD 或 SSD）
* 相同的接口类型（例如 SAS）




[[how-to-identify-hot-spares]]
== 如何识别热备盘

您可以通过 Initial Setup Wizard 或从 Hardware 页面分配热备件。要确定是否分配了热备件，请转到 Hardware 页面并查找以粉红色显示的任何驱动器托架。



[[how-hot-spare-coverage-works]]
== 热备件覆盖范围的工作原理

热备件覆盖范围的工作原理如下：

* 将未分配的驱动器保留为 RAID 1、RAID 5 或 RAID 6 卷组的热备盘。
+
[NOTE]
====
热备盘不能用于池，池具有不同的数据保护方法。池不会预留额外的驱动器，而是在池的每个驱动器内预留备用容量（称为 _preservation capacity_）。如果池中的驱动器出现故障，控制器将在该备用容量中重建数据。

====
* 如果 RAID 1、RAID 5 或 RAID 6 卷组中的驱动器出现故障，控制器会自动使用冗余数据从出现故障的驱动器重建数据。热备盘会自动替换出现故障的驱动器，而无需进行物理交换。
* 物理更换故障驱动器后，将执行从热备盘驱动器到更换驱动器的复制操作。如果您已将热备盘驱动器指定为卷组的永久成员，则不需要执行复制操作。
* 卷组的托盘丢失保护和抽屉丢失保护的可用性取决于构成卷组的驱动器的位置。由于驱动器故障和热备盘驱动器的位置，托盘丢失保护和抽屉丢失保护可能会丢失。为确保托盘丢失保护和抽屉丢失保护不受影响，您必须更换出现故障的驱动器以启动复制过程。
* 在更换故障驱动器时，存储阵列卷保持联机并可访问，因为热备用驱动器会自动替换故障驱动器。




[[considerations-for-hot-spare-drive-capacity]]
== 热备盘容量注意事项

选择容量等于或大于要保护的驱动器总容量的驱动器。例如，如果您有一个配置容量为 8 GiB 的 18 GiB 驱动器，则可以使用 9 GiB 或更大的驱动器作为热备盘。通常，请勿将驱动器分配为热备盘，除非其容量等于或大于存储阵列中最大驱动器的容量。

[NOTE]
====
如果没有具有相同物理容量的热备盘，则如果驱动器的"已用容量"等于或小于热备驱动器的容量，则可以将容量较低的驱动器用作热备盘。

====


[[considerations-for-media-and-interface-types]]
== 介质和接口类型的注意事项

用作热备盘的驱动器必须与其要保护的驱动器共享相同的介质类型和接口类型。例如，HDD 驱动器不能用作 SSD 驱动器的热备盘。



[[considerations-for-secure-capable-drives]]
== 具有安全功能的驱动器的注意事项

具有安全功能的驱动器（如 FDE 或 FIPS）可以用作具有或不具有安全功能的驱动器的热备盘。但是，不具备安全功能的驱动器不能用作具有安全功能的驱动器的热备盘。

当您选择要用于热备盘的启用了安全的驱动器时，System Manager 会提示您执行安全擦除，然后才能继续。安全擦除将驱动器的安全属性重置为支持安全，但不启用安全。

[NOTE]
====
当您启用驱动器安全功能，然后从具有安全功能的驱动器创建池或卷组时，驱动器将变为_安全启用_。只能通过配置了正确安全密钥的控制器进行读写访问。这种增加的安全性可防止对从存储阵列中物理移除的驱动器上的数据进行未经授权的访问。

====


[[recommended-number-of-hot-spare-drives]]
== 建议的热备用驱动器数量

如果您使用初始设置向导自动创建热备盘，则 System Manager 会为特定介质类型和接口类型的每 30 个驱动器创建一个热备盘。否则，您可以在存储阵列中的卷组之间手动创建热备盘驱动器。
